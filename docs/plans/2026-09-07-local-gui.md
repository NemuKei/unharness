# Local fixture GUI implementation plan

> **For agentic workers:** use superpowers:subagent-driven-development for the independent implementation and review tasks; keep progress in this plan's ignored workspace.

**Goal:** A local PixiJS GUI can save, select, apply, observe and restore owned fixture loadouts using the existing core.

**Architecture:** A loopback Node HTTP adapter owns one selected store/scope. React/TypeScript consumes redacted state and paginated summaries; PixiJS receives visual state only. Existing core operations retain configuration and recovery authority.

**Tech stack:** Node.js 24+, React, TypeScript, Vite, PixiJS 8.20.1, Node test runner.

**Spec:** [docs/spec-gui.md](../spec-gui.md), [visual direction](../design.md).

## Global constraints

- Work directly on main as previously authorized; preserve independent user changes.
- Unharness is free/local and requires no paid API, hosted backend or runtime model call.
- Target native macOS and Windows; a Mac GUI check does not verify Windows or complete desktop support.
- Only owned synthetic fixtures may change; preserve task requirements, permissions, independent edits and recovery.
- Both `runtimeStateVerified` and `modeSwitchingVerified` remain false.
- No raw transcripts, personal settings, fixture seeds or local test data in Git.
- Use the selected PixiJS + HTML/CSS split and the existing dark machine-hangar art direction.

## Task 1: Loopback service and CLI

**Files:** create `src/gui/controller.mjs`, `src/gui/server.mjs`, `src/gui/cli.mjs`, `test/gui.test.mjs`; modify `bin/unharness.mjs`. Do not modify frontend files or package dependencies in this task.

**Interfaces:** `createDemoWorkspace({ parent })` returns `{ store, scopeId, fixture, project }`; `createGuiController({ store, scopeId, codexHome? })` returns `{ state(), favorites(after?), checkpoints(after?), execute(action, body) }`. `startGuiServer({ store, scopeId, assetsDirectory, port?, codexHome? })` returns `{ server, url, close() }`. `guiMain(argv, { stdout, stderr })` implements `gui --demo [--parent <existing dir>] [--port <0..65535>]` or `gui --store <store> --scope <hash> [--port ...]`. `--help` must not create anything. The full HTTP/state contract is in the spec.

- [ ] Write meaningful failing server/controller tests first, using real fixtures, not fake service outputs. For example, restore a selected favorite, alter an owned source independently, and assert a later apply fails without changing that source. Assert duplicate requests return one application/checkpoint identity. Test untrusted HTTP inputs before any write.
- [ ] Run `node --test test/gui.test.mjs` and capture the missing-feature failure.
- [ ] Implement the controller through `createStore`, fixture helpers and shared loadout operations. Use core validation for scope/targets and a safe error allowlist. Paginate favorite/checkpoint summaries. Never reconstruct files from displayed case labels.
- [ ] Implement static allowlisting and the HTTP contract. Bind loopback only; validate Host, Origin/Fetch metadata, client header and token before reading request bodies/dispatch. Bound JSON body size at 16 KiB. Serialize POST operations and retain up to 1000 request identities per launch; reject further new identities rather than evicting. Exact duplicate action/body returns cached success/failure; a changed payload for an ID is rejected.
- [ ] Implement explicit demo setup and resume CLI. Three named saved conditions finish at baseline. The server starts only after the build exists. Preserve new workspaces on exit/failure with recovery paths available.
- [ ] Run covering tests and self-review; commit only this task's files and report contract details and limits.

## Task 2: Local artwork, React surface and PixiJS

**Files:** root owns `package.json`, lockfile and build setup; create `web/index.html`, `web/src/{main,App,api,types,Hangar,renderer}.tsx/ts`, focused UI components and CSS, `web/assets/` and `web/tsconfig.json`, `vite.config.mjs`. Frontend implementer owns `web/` and Vite/TS config only; coordinator integrates package scripts/dependencies.

**Interfaces:** use the spec's HTTP routes and shape. Lazy-load the PixiJS scene after HTML controls render. Provide visible state for loading/disconnected/conflicted operations, application boundaries, optional naming, favorite/checkpoint paging and selected-task observation. Keep per-frame animation outside React state.

- [ ] Inspect the accepted images and extract shared tokens, columns, typography, borders, buttons and asset framing. Record functional copy changes required by the fixture scope.
- [ ] Produce and inspect a bundled three-state scene sheet with no UI text. Record the prompt and source references. Art represents diagnostic conditions only; overlays/labels remain DOM.
- [ ] Install exact compatible React/Vite/TypeScript dependencies; add `build`, `check` and `gui` commands. Preserve Node-only test execution without installed frontend packages.
- [ ] Build the functional surface around the actual API. Review plan before apply, disable double clicks, never automatically retry mutations, show failures without claiming success. Permit actual source state to differ from selected preview. Save uses current prepared state, not selected preview.
- [ ] Implement PixiJS frame selection and restrained light/particle animation; dispose on unmount and stop for off/reduced motion/hidden tabs. Catch graphics initialization failure and keep controls usable.
- [ ] Run TypeScript and production build, then exercise browser interactions against Task 1. Fix visual/functional failures and commit the surface.
