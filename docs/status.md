## Established

- Product name: **Unharness**.
- Free to use, with no required paid API, hosted backend, or recurring operator service expense. The user's own AI subscription/usage is explicitly outside this boundary. Default artwork, image composition/import, storage, card export and sharing preparation run locally.
- Value: easily take off and compare harness configurations, then keep the setup that fits the current model, environment, and work.
- Mode labels: **限定解除 — UNSEAL**, **零式 — TRUEFORM**, and Normal loadout.
- Delivery priority updated on 2026-09-09: finish the complete Mac Codex product first. The maintainer deferred Claude Code until they have capacity; keep its existing implementation and regression coverage, but do not require its native qualification for the initial Mac release. Windows follows later, Codex before Claude Code; see [delivery](delivery.md).
- Required experience: save, three modes, truthful state, fresh comparison, favorites, recovery, web and AI entry points, and optional effects.
- Initial release scope centers on user-authored/personally added optional instructions and automatic Skills, with optional hooks secondary. Memory, native continuity and the Unharness management/control Skill remain retained, including in TRUEFORM. The 2026-09-09 [AI-guided setup contract](spec-guided-setup.md) refines the mode choices and new-Skill handling; the [registered user-source contract](spec-user-sources.md) records the currently qualified earlier write boundary. Preserve versions during migration.
- The maintainer clarified that the primary experience uses one selected mode for a task. Record ordinary use and offer an optional later sequential replay; automatic simultaneous multi-mode dispatch is outside initial scope and remains technically unverified.
- Numerical comparison now records persisted Codex root-response usage/time beside attributed retrospective checks, ratings and notes. It keeps partial/missing coverage explicit and does not run an automatic grader. See the [measurement contract](comparison-metrics.md).
- The registered-source workbench has Equipment and Comparison tabs. One to three ordinary-run versions appear as compact historical portraits, an aligned table and a zero-based token chart, and a matched historical configuration can be saved as a favorite without applying it. These are scoped observations; the revised product does not gate artwork creation on them.
- Appearance and performance are independent under the 2026-09-09 revision. Performance is displayed as evidence-backed text/numbers; it does not force the selected image into GOOD/BAD treatment.
- Selected visuals: pixel-art machine hangar, progressive exposure of the inner AI, and a divine luminous reveal.
- Selected rendering stack: PixiJS for the entity, armor and effects; HTML/CSS for controls and readable state; reviewed PNG sprites plus versioned JSON recipes/pixel data. The maintainer accepts additional dependencies. See [the rendering decision](design.md#selected-rendering-stack).
- Prepared/random default discovery remains available. Original creation is voluntary at any time through the user's own AI and a bundled authoring Skill, with local import and reusable collection versions. [The new appearance contract](personalization.md) removes comparison unlocks, three-candidate/final-choice limits and forced BAD art.
- Original templates define three logical parts: AI entity, restraints and background. Users can replace one part or a complete set; compatible prepared parts, anchors and mode poses support composition. The old appearance core and unfinished GUI/API work still need migration and rendered verification.
- [Build-card export/X preparation](build-cards.md) remains planned with local image saving as a fallback and explicit user posting. Reusable artwork packs and public discovery are later design work after local creation/save/reuse; they do not add a public gallery requirement to Mac completion.
- The accepted primary entry is a user-owned domain inside the AI app's browser, opened through the Unharness management Skill. [The domain-entry contract](spec-domain-entry.md) includes local pairing, source privacy and offline recovery; the maintainer authorized a subdomain under the existing SideBiz site. The selected destination is `https://unharness.deltahelmlab.com`, with a small DeltaHelm Lab link to `https://deltahelmlab.com/`. Cloudflare Pages hosting remains separate from the existing landing-page project; DNS binding and deployment are not yet verified.
- The [Mac product plan](superpowers/plans/2026-09-09-mac-product-experience.md) includes the five recommended UX items: a synthetic demo, clear connection identity, fresh-task guidance, offline recovery and retained Unharness controls, plus a small author/site footer. These are planned changes, not newly verified runtime behavior.
- Initial README drafts, specification, architecture boundaries, compatibility criteria, and handoff plan are present.
