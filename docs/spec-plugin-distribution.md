# Unharnessプラグインの配布と版管理

2026-09-09の利用者の提案・同意に基づく。初回のMac Codex版は、管理・設定相談・オリジナル制作のSkillとローカルMCPを一つのUnharnessプラグインにまとめる。公開ページの操作は[WebMCP](spec-domain-entry.md)でも提供し、同じローカル処理を呼ぶ。公式ディレクトリへの掲載審査は初回のMac完成条件にしない。

開発用の[パッケージ作成](plugin-package.md)では、Mac arm64向けに公式Node・既存UI・MCP・管理／設定相談／制作Skillをまとめ、ファイルの版とハッシュを記録できる。隔離したCodexへの実導入と初回保存・3モードには[限定した検証記録](evidence/2026-09-09-plugin-package-macos.md)がある。[更新・削除・再導入と独立した復旧画面](evidence/2026-09-09-plugin-recovery-macos.md)に加え、[v2設定・作品保存と削除後の復旧](evidence/2026-09-10-native-package-v2.md)を確認した。制作Skillの実際のモデル呼出し、利用者向け導入と公開接続は引き続き検証する。

## 配布物と保存データ

公開目的は、無料で使える面白い作品を届け、外部から確認できる制作実績を積むこと。利用者は2026-09-09にMITでのOSS公開を選択した。公開サイト・プラグイン・GitHubの実装と検証資料を一つの作品として整え、作者サイトへつなぐ。プラグインのライセンスはルートの[MITライセンス](../LICENSE)と揃え、外部コンポーネント固有の表示も配布物へ残す。

- プラグインは管理の入口、相談・制作の手順、ローカルの起動・操作・復旧処理、必要な実行用ファイルを同じ版として配布する。Cloudflareなど開発者用のSkillや認証情報は含めない。
- ポータブルなルート`plugin.json`を基本とし、実際のCodexで必要な`.codex-plugin/plugin.json`互換情報も用意する。同じ版・名前を使い、二つのマニフェストを別製品として更新しない。
- Normal、解除モードの保存版、お気に入り、比較、作品は、プラグインのインストール・キャッシュ先の外へ保存する。プラグインの再インストール、更新、以前の版への切替で消さない。
- プラグイン版、公開UI版、ローカルAPIの対応版、保存データの形式を別に記録する。接続時に対応を照合し、互換性がない組合せからの変更要求を拒否する。公開サイトだけの更新で利用者のNormalやプリセットを書き換えない。
- データの形式変更は旧版を保持する明示的な移行にし、未対応の旧アプリが新形式へ書き込まない。設定・作品の変更とプラグイン更新を混同しない。
- TRUEFORMでもプラグインの管理Skillと必要な接続を保持する。任意の制作手順の自動使用を抑えるために、プラグイン全体を無効にしない。

## 検証と配布先

開発中は個人用マーケットプレイスで導入・更新・新規タスクでの読み込みを確認する。配布候補を作った後、公開前にソース・ライセンス・配布先を提示し、承認した対象だけを公開する。Git由来の配布物はタグまたはコミットを固定し、公開ページに導入対象の版を表示する。非公開リポジトリを未認証の利用者が取得できるとは案内しない。

OpenAIの公式ディレクトリにはSkillのみ、リモートMCPのみ、または両者を含むプラグインを申請でき、審査・承認後に公開する。2026-09-09時点の通常のMCP申請は公開HTTPSエンドポイントを要求し、ローカルMCPは別途相談する扱いである。Unharnessのローカル設定処理を、掲載のために公開サーバーへ移さない。公式掲載が必要になった段階で、その時の条件と利用可能な配布形式を確認する。

導入・更新の検証では、管理SkillとMCPの実際の導入先・版、全モードの起動と復旧、新規タスクでの読み込み、旧データの保持、古いUIとの接続、途中失敗を確認する。プラグインの登録成功だけで製品の一巡が完了したとは扱わない。

参照: [OpenAIのプラグイン配布仕様](https://developers.openai.com/plugins/build/plugins)、[公式ディレクトリの申請条件](https://developers.openai.com/plugins/deploy/submission)。
