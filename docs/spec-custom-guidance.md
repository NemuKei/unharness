# 限定解除の追加指示を保存する

2026-09-20。利用者が、推奨ルールを保存・利用できる限定解除への拡張を承認した。

## 受け入れ条件

- v4の設定提案は通常Skillのv3状態・継承規則を維持する。
- UNSEALは `minimal / none / custom` を選ぶ。`custom` の場合だけ `customInstructions` の本文を必須にする。本文は空白だけを拒否し、UTF-8で8192バイト以下、制御文字と不正なUnicodeを拒否する。
- 本文は追加指示のデータとして検証・固定保存し、読取中に実行しない。パス、認証情報、権限、実行コマンドを保存先として入力させない。
- TRUEFORMは追加指示なしを維持し、UNSEAL本文を合成・出力しない。Normalは保存した元の内容へ戻る。公式プラグインはNormal状態を保持する。
- review_setupは両方の構成を固定し、apply_setupは記録だけを保存する。準備は既存plan_mode/apply_planの別操作とする。
- v4のwriter fenceを採用し、v1/v2/v3の不変記録・お気に入り・中断復旧を維持する。旧writerはv4の実データへ書けない。
- 追加登録後もv4を維持する。v4のSkill状態一覧は既存のinventory v2を再利用する。
- GUIは保存したカスタム指示というラベルと本文を表示する。詳細な本文作成はAI相談から行い、通常画面に新しい大きな編集フォームを足さない。
- 原本・プラグインキャッシュ・別の常時読み込み設定は直接変更しない。
- 保存時のプラグイン／ネイティブ版の不一致は別の移行境界。機能実装の都合で検証を無効化して実環境へ適用しない。

## 実装と検証

1. 失敗するテストを先に追加する。本文の入力制約、UNSEAL/TRUEFORMの分離、表示と版の互換性を対象にする。
2. 本文の検証・識別情報を一か所に集約し、保存形式v4と既存のcompiler/CLI/MCPへ接続する。
3. 設定採用・復帰・追加登録・中断復旧のv4経路を検証する。旧v3記録とNormalのバイト一致、独立編集の拒否を確認する。
4. GUIの型と表示、AI相談文、説明を更新する。locked dependencies、check/build、対象のブラウザー経路を確認する。
5. 独立レビューの指摘を直し、今回の差分を既存作業へ非破壊で統合する。元の66ファイルの未確定変更は一括commit・上書きしない。
6. 配布済み版と個人設定への反映は、対応版・復帰経路・競合状態を別に確認してから扱う。未確認の段階を適用済みとはしない。

## 特に確認する入力

- 空白のみ、NUL、C1制御文字、不正なサロゲート、UTF-8の境界を超える日本語。
- custom以外への本文添付、custom本文欠落、TRUEFORMへの本文注入、未登録の指示対象。
- 保存後の本文改ざん、古いreviewの再使用、独立した設定変更。
- v3→v4採用中の各中断点、旧お気に入りとNormalの復帰、v4での登録追加。
- UIの保存と準備の違い、本文の安全なテキスト表示、旧版の説明が変わらないこと。
