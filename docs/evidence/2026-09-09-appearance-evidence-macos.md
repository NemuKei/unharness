# Appearance evidence gate on macOS

The isolated appearance branch now connects a predeclared comparison rule to canonical saved replay results and the existing local appearance journal. These tests use newly owned synthetic profiles and synthetic recording equivalents of the previously qualified Codex format. They are implementation evidence; they are not new desktop runs, real performance results or rendered original forms.

```text
node --test --test-concurrency=4 test/appearance-rule.test.mjs test/appearance-lifecycle.test.mjs test/appearance-store.test.mjs test/appearance-evidence.test.mjs test/starting-conditions.test.mjs test/replay-results.test.mjs
```

Result: **56 tests passed, zero failed, zero skipped** on the Mac development host. The new rule/evidence tests were first run against missing/unsupported behavior and failed, then passed after implementation. A fixture initially omitted Codex's effective override file from its synthetic recording; correcting that fixture restored the intended source-match test without weakening the matcher.

The checks cover strict optional rule preservation; invalid/nonexistent snapshot refusal; all declared attempts and latest corrections; known quality, counters and runtime conditions; failure-inclusive tokens per accepted task; missing/unfinished/extra observations; stable achievement identity across title changes; exact three-candidate creation; final adoption; duplicate calls; interruption/recovery without rerolling; changed current mode and a late independent source edit. The earlier store checks also kill a real child writer and recover its exact saved appearance state.

Creation reads current source bytes, retained inputs and the native configuration preflight again. It does not claim a fresh desktop observation from that preflight. Appearance writes remain separate from source settings and source recovery. Ordinary records or declarations without a rule do not qualify.

The internal service is ready for the renderer and transport integration. The built GUI, natural-language appearance operations, reviewed candidate artwork, collection presentation, cards and first-user/release journey remain to be implemented and verified. The independently owned Claude integration remains a separate delivery and review boundary.
