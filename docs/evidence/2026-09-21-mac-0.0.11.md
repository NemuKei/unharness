## Native update and recovery

Tests used macOS 26.6.2, official Codex CLI 0.153.4 and freshly owned synthetic
homes/projects. No credentials, model request or real user workspace was used.
The old 0.0.10 archive was independently downloaded and fully verified first.

The native CLI installed 0.0.10. Its packaged services saved Normal, an old
favorite and v3 setup, then prepared TRUEFORM. Updating to 0.0.11 preserved those
records and selected sources. The CLI changed the marketplace path and reordered
TOML tables; retained values and metadata were checked separately from selected
instruction/Skill bytes. Reviewing and accepting the exact retained-only change
did not write managed files. Normal and the historical favorite restored correctly.

A source replacement was deliberately interrupted by adding an invalid
marketplace after removing the previous registration. The installed cache and
saved state survived. Restoring the original source and installing 0.0.10 recovered
the native installation while the workspace still used v3. Its saved Normal and
setup remained readable. This tests an actual failed replacement, not just a
successful version round-trip.

The final ZIP was then installed as 0.0.11. A fresh packaged MCP reported the
exact final distribution ID and exposed 69 tools. An existing old GUI was replaced
through the authenticated launcher: launch/runtime identities changed, the old
port closed, and new served HTML matched the final archive. The in-app browser
showed saved custom instructions as text and screen version 0.0.11, without
console warnings/errors.

Explicit v4 adoption left source files unchanged until a separate mode apply.
UNSEAL used the saved custom body; TRUEFORM removed it; Normal restored selected
source bytes. The original Normal record remained immutable. The actual old
packaged writer refused v4 with `workspace-invalid`, without changing sources.

After stopping the owned GUI, native plugin removal deleted its cache. The
synthetic plugin-data directory was also removed. The verified independent
0.0.11 recovery copy, using its own bundled Node and recovery controller, restored
Normal while preserving current shared settings. Release withdrawal or a catalog
downgrade is not v4 recovery; [the update guide](../plugin-update.md#recovery-after-adopting-setup-v4)
requires a compatible recovery copy or corrected release.
