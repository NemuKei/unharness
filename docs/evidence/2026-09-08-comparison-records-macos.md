# Ordinary comparison records on macOS

The registered-source service, CLI and built workbench can record one selected task, save immutable attributed assessments, compare up to three saved versions, inspect an explicitly requested answer and save a historical configuration as a favorite. These are ordinary-use observations; they remain neutral and do not unlock original-form creation.

## Revision and environment

- Final implementation: `f9c7ee17f0efaecb645f5f27d827d6599373aaf8`.
- Native macOS 26.6.2, arm64; Node.js 24.20.0.
- Codex executable: 0.153.4. Its already recorded desktop format is the supported measurement source; the current process OS is recorded separately from unknown historical execution OS/product values.
- Built Vite GUI, installed Chrome 152.0.7977.82 and an existing Playwright runtime. The Browser plugin was unavailable, so the documented regular-Playwright fallback was used without adding an application dependency.
- Normal browser viewports: 1440 × 1000 and 390 × 844; failure-path inspection also used 1280 × 900. Effects off and reduced motion were included.

Real-record inspection reused four previously authorized Mac pilot recordings, including one known two-turn case. No new desktop/model task was started. Those earlier operator receipts were not retrofitted to newer preparation boundaries. All service/GUI writes used marked temporary owned profiles and synthetic task records. Personal configuration, raw conversations, task identifiers, output bodies and screenshots remain outside Git.

## Decisions retained

- Retrospective checks remain attributed observations. They do not relax the declared comparison/achievement gate; pre-use capture and replay still need implementation. The cost is that ordinary history alone cannot unlock an original appearance.
- The adapter uses fixed diagnostic/error terms, keeping native values out of public errors. New formats may need a vocabulary/adapter update rather than leaking unsupported details.
- Lifecycle replays are deduplicated from original recognized records before lossy normalization. Ambiguous or distinct malformed records remain unavailable instead of becoming a false qualified capture.

Pre-use request/starting-file/criteria capture, explicitly requested sequential replay, AI/MCP operations, Claude Code integration and Mac product/release completion remain separate work. These checks establish neither a performance benefit nor complete runtime, full mode-switch, Windows or Claude Code support.
