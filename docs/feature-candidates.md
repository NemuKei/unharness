# 追加機能の候補

2026-09-06。利用者の「他にどういう機能があるとウケるか」への提案。需要を確認する前の仮説であり、採用済みの初期仕様や実装タスクではない。現在のCodex対応・Windows検証の優先順位は変えない。

## 推奨する方向

Unharnessらしい強みを伸ばす本命は「装備の切り分け検証」。公開後に発見を伝えやすくする候補は「ビルドカード」。継続して使う土台には、実際の仕事を保存する「マイクエスト」が合うと考える。

| 候補 | 体験 | 刺さりそうな理由 |
| --- | --- | --- |
| この1回だけ試着 | 次の依頼だけ別の装備で試し、終了後に以前の装備へ復帰する | 戻し忘れを気にせず試し始められる |
| 装備の切り分け検証 | 選んだSkill等を一つずつ外し、回数・予算を決めて同じ課題で比較する | どの構成を残すかの判断に理由が生まれる |
| マイクエスト | よく頼む修正・レビュー・文章作成を、開始条件と合格条件ごと保存する | 自分の実務で装備を試せ、モデル更新後にも繰り返し使える |
| ビルドカードと構成レシピ | 機体の姿、装備構成、モデル、比較条件、結果と本人の一言を書き出す | 自分の発見を見せやすく、見た人も同じ条件を試しやすい |
| 更新後の再試着 | 確認できたモデル・Skill・アプリの変更時に、保存クエストの再比較を提案する | 環境が変わった後にも装備を選び直せる |
| 装備の発動リプレイ | 取得できた読み込み・呼び出し・修正・再試行のログを時系列で見せる | 点数だけでは分からない進め方の違いを確かめられる |

## 成立に必要なこと

- ワンショット試着は、タスクへの適用範囲と復帰を検証できることが前提。全体設定の変更しかできない場合に、他タスクからの分離を保証しない。
- 切り分けは、品質条件・試行予算・失敗と変動を記録する。一つの差を単品の普遍的な効果や因果と断定しない。組み合わせの相互作用は追加の検証として扱う。
- マイクエストは、装備の版と課題・合格条件の版を別に保存する。
- ビルドカードは実測とサンプルを区別し、比較条件と試行数、公開する項目を利用者が選べるようにする。[Xへの共有](build-cards.md)はPNG画像のクリップボードコピーと、OSS公開リンクを含む文案入り投稿画面への移動を主操作にする。利用者が画像を貼り付けて投稿し、コピーできない場合は画像保存を使う。共有マーケットは必要ない。個人の設定・秘密情報・会話を丸ごと公開しない。
- 更新後の再試着は、見える変更を起点に利用者が再実行を選ぶ。見えないモデル内部更新の自動検出や、無断での有料評価実行を前提にしない。
- 発動リプレイは観測可能な実行ログが前提。未観測を未発動と扱わず、原因を推測だけで表示しない。

## 最初に組み合わせるなら

基本の保存・切替・比較・復帰が成立した後、**マイクエスト → 装備の切り分け → ビルドカード**をつなぐ案を推奨する。自分の課題を繰り返し試し、相性を発見し、役立った構成と根拠を残して伝えられる。

利用者はこの方向に賛成し、オリジナルの姿については「好みへの最適化」よりもランダムな出会いを希望した。既定では用意したパターンを確率的に適用し、ユーザー環境での制作は任意とする案。ドット絵はパーツ合成やコード描画でも作れる。付属する制作Skill、メモリーによる課題・評価基準・装備候補の提案、比較中の条件固定は[外観とメモリーの案](personalization.md)へ記録した。方向への賛成であり、すべてを初期リリースへ含める決定ではない。

利用者は、性能に基づく条件達成時だけオリジナル制作を解放し、「3案から一つを選んで確定」してXに投稿しやすくする方向を採用した。条件判定と候補の保存はGUI・AIで共通にし、生成失敗の再試行と創作上の引き直しを区別する。Unharnessは無料・運用サービス費ゼロを前提とし、標準の3案制作はローカルで成立させる。ユーザー自身のAI契約・使用量は別枠。採用された仕様は[製品契約](spec.md)と各機能の文書が正本であり、この候補一覧に残る他案まで採用されたわけではない。

ワンショット試着は、タスク単位の分離が成立する場合に特に強い入口になる。更新後の再試着と発動リプレイは、比較記録と実行観測が育った段階で広げる。

ブラインド比較、数値評価、お気に入り、共鳴装備の表現はすでに設計へ入っているため、新規候補として数え直さない。

## 反応を確かめる

試着が実際に別構成を試すきっかけになるか、保存クエストで別の日にも比較を再開するか、切り分け結果が採用・維持・復帰の判断を変えるか、カードを見た人が条件を理解して試したくなるかを見る。利用回数だけで成功とせず、判断がしやすくなったかを確かめる。

## 参考

[PromptfooのWeb viewer](https://www.promptfoo.dev/docs/usage/web-ui/)には結果比較、編集して再実行、採点・コメント、出力がある。[共有機能](https://www.promptfoo.dev/docs/usage/sharing/)では評価結果のスナップショットを共有できる。比較から再実行・記録・共有へつなぐ体験の参考とした。これらの存在だけで、Unharnessの候補機能に需要があると証明されたわけではない。
