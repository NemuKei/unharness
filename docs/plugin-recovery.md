# プラグイン削除後の復旧

復旧用の実行環境・UIは、登録したCodexホームの`.unharness-workbench/recovery`へ配布物の識別子ごとに保存する。元の配布物とコピーした全ファイルのハッシュを確認し、既存の版・独立した編集・中断したコピーを上書きしない。保存した`.command`は、Mac標準のチェックサム機能でNodeと最小の検証コードを照合してから実行する。その検証コードが配布物全体を確認した後に、復旧画面の処理を読み込む。Normal、プリセット、お気に入りなどの保存場所は移動しない。

## ローカル操作の契約

利用者は保存された`Open Unharness Recovery.command`を開く。これは復旧画面を開くだけで、設定変更は行わない。CLIは自動化と診断にも使える。引数はすべてローカルで確定し、環境変数や現在のディレクトリから対象を推測しない。

```text
scripts/unharness plugin recovery --data-directory <native-plugin-data>
scripts/unharness recovery <open|status|stop> --directory <saved-workbench-directory> --binding-id <hash> --distribution-id <hash> [--browser]
```

`plugin recovery`は設定済みの対象へ実行中の配布版の復旧コピーを準備する。`recovery open`は同じ対象の既存画面を確認し、必要なら認証した自分の画面を停止して復旧画面を開く。`--browser`は`open`だけに指定でき、macOSの既定ブラウザーで確認済みのloopback URLを開く。`status`は起動せず、`stop`は自分の認証できる画面だけを停止する。出力はJSON、エラーは秘密や設定本文を含まない種別を標準エラーへ返す。終了コードは成功0、操作失敗1、引数不正2。対話プロンプト、任意コマンド、リモートURL、ブラウザーからのパス指定は受け付けない。

復旧画面は保存状態の確認、中断した処理の復旧、保持対象だけの独立編集の確認・採用、Normalの復帰計画・適用を提供する。Normal以外の計画、別画面で作った計画、対象登録や追加、設定相談、外観変更は受け付けない。変更後の表示は保存ファイルの準備状態であり、実行中のAIタスクへの反映を意味しない。

通常のNormal復帰と中断処理の復旧は同梱Nodeだけで実行する。Codexの設定ファイルに独立編集がある場合の意味的な照合には、登録時に選んだローカルCodex実行ファイルを使う。モデル呼び出しやネットワーク通信は行わない。実行ファイルが使えない、管理対象も変わった、照合できない場合は編集を残して停止する。

配布物の内容索引はコピーの整合性を確認するものであり、公開者の署名の代わりにはならない。新しい版は別コピーとして保持する。古い保存形式に対応しない復旧版は、読めないデータを推測して変更しない。

実装・検証の状態は[現在の状態](status.md)と[配布物](plugin-package.md)で個別に記録する。
