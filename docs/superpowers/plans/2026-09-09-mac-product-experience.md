# Mac版の導入・AI操作・オリジナル外観 実装計画

> **For agentic workers:** Use `superpowers:executing-plans` to implement the linked plans task by task in this task. Keep unrelated work intact. Do not start subagents or another user task merely because this plan exists.

**Goal:** 独自ドメインのUnharnessをCodex Desktopのアプリ内ブラウザーから開き、手元の設定を管理し、自由に作ったドット絵を使える初回のMac版を仕上げる。2026-09-09の利用者の指定により、Claude Codeの実機確認は余裕ができた時の後続とし、今回の完成条件にしない。既存のClaude実装と共通設計は保持する。

**Architecture:** 画面の配信、PC内の設定処理、AIへの相談、外観データを分ける。公開サイトは画面・案内・デモを配信し、個人設定と作品はPC内で管理する。GUIとAIは同じ決定的な操作を使い、性能評価は見た目から独立させる。

**Tech Stack:** Node.js 24+、既存のReact / TypeScript / Vite / PixiJS、ローカルMCP、CodexとClaude Code Desktopの既存のアプリ内ブラウザー。

**Spec:** [製品仕様](../../spec.md)、[独自ドメインとAIの入口](../../spec-domain-entry.md)、[AIによる設定相談](../../spec-guided-setup.md)、[外観](../../personalization.md)、[共有](../../build-cards.md)。

関連SkillとローカルMCPを一つのプラグインにまとめ、公開ページにもWebMCPの操作口を用意する。[プラグインの配布・版管理](../../spec-plugin-distribution.md)に従い、利用者の保存データを更新対象のプラグインとは別に保持する。公式ディレクトリ掲載は完成後の検討とする。

## この計画が置き換える判断

2026-09-09の利用者の選択を反映する。以下は採用した方向であり、既に動作するという意味ではない。

| 項目 | 採用する体験 |
| --- | --- |
| 日常の起動 | Codex / Claude Code Desktopに「アンハーネスを開いて」と頼み、同梱の管理Skillを通して開く |
| 見えるURL | 利用者所有の独自ドメイン。PC内の処理との通信にはローカル接続を使う |
| 導入 | サイトから対応AIを選び、導入手順に進める。GitHubやターミナルだけを入口にしない |
| 日常のGUI | モード切替を中心にし、細かい設定は「設定をAIに相談」から普段のAIへ渡す |
| Normalの役割 | 従来の構成を保存して保持する。初回の棚卸しで再設計した構成へ置き換えない |
| 初回の棚卸し | 従来の構成をNormalとして保存し、解除対象を確認した後、零式の新規タスクで限定解除・零式の構成を作ることを推奨。現状のまま相談する経路も残す |
| 零式の例外 | Unharnessの管理Skillと起動・状態確認・切替・復旧に必要な接続を保持する |
| オリジナル作成 | いつでも任意に開始し、希望・参考画像をAIと相談して作る。比較成績による解放条件を設けない |
| ドット絵の構成 | AI本体・拘束具・背景の3つを論理パーツとする。既存パーツとの組合せと部分的な作り替えを可能にする |
| 見た目と性能 | 見た目は自由に選ぶ。性能は別の数値・説明として表示し、BAD画像へ強制しない |
| 作品の保存 | パーツ画像と版をローカルに読み込み、以前の作品も残す。3候補限定・一度だけの最終選択を廃止する |
| 作者の導線 | 画面の最下部に小さな作者表記とサイトへのリンク。共有カードでも確認可能にする |
| 後続の共有検討 | 画像を見せる導線と、パーツ一式を他の人が使えるようにする導線を分ける |

## 維持する条件

- 初回のmacOS版はCodex Desktopで完成させる。Claude Codeは後続とし、WindowsではCodex、Claude Codeの順に対応する。[更新した受け渡し順](../../delivery.md)に従う。
- 有料API、個人設定を扱う運用サーバー、新規の継続課金サービスを必須にしない。任意の制作や相談は利用者自身のAI利用枠を使う。
- 専用の`.app` / `.exe`配布、開発者登録、署名サービス購入を初期体験の前提にしない。必要なら費用と具体的な配布物を別途レビューする。
- メモリ、作業継続、権限、管理ポリシー、必須のプロジェクト要件を保持する。
- 実際の追加ソースを勝手に自作・任意と判断して登録しない。現在の登録範囲も計画更新だけでは変えない。
- 設定準備と、特定の新規タスクで確認できた状態を分ける。今の会話への即時反映を表示しない。
- ローカルの接続認証、競合確認、復旧を維持する。公開UIからファイルパスや任意コマンドを指定できるAPIを作らない。
- 技術的な再送は同じ操作として扱う。一方、利用者が新しい作品や修正を求めることを回数制限で妨げない。
- 公開・外部投稿・新規有料契約は、この計画の保存だけでは実行しない。

調査時点の作業ブランチは`codex/mac-finish`、最後のコミットは`eaddf7a`。Codexの登録済み範囲のMac一巡には実機証拠があり、ClaudeのMacアダプターは統合レビュー中である。Claudeの新規ネイティブタスクでの読み込みとAI接続は未完了。詳細は[現在の状態](../../status.md)と[統合レビュー](../../evidence/2026-09-09-mac-integration-review.md)を参照する。

作業ツリーには外観のAPI・描画接続と、設定プリセットの途中変更がある。新計画に合う部分を確認して再利用し、途中変更を上書きしない。現在のHTTPサーバーはlocalhost専用で、独自ドメインからの接続を受け付けない。旧外観コアには比較による作成制限とBAD強制が残る。この計画の完了チェックには使えない。

## 導入・デモ・作者の導線

**責務とファイル:** 既存GUIの操作ロジックを公開用画面へコピーしない。`web/src/entry/`に導入・接続前・デモの表示を置き、`web/src/SourceWorkbench.tsx`への接続を分ける。`src/setup/`がローカル導入先とバージョン確認を担当する。フッターは`web/src/BrandFooter.tsx`、公開先の設定は`web/src/site-config.ts`に集約する。公開前に実在するファイル名を再照合し、名称だけを理由に既存の責務を移さない。

- [ ] サイトの最初の選択を「試してみる」「自分のAIに導入する」「接続して開く」にする。インストール済みと未接続を同じ状態として扱わない。
- [ ] 導入ではCodex / Claude CodeとOSを確認し、その組合せで検証したプラグイン導入またはAIへの導入依頼を案内する。直接導入の公式経路がない場合は、その制約を明示したコピー導線を使う。未公開の配布物にダウンロードボタンを付けない。
- [ ] 既存のNode.js 24+または検証済みの同梱実行環境を使えるようにし、利用者自身によるGit clone・npm操作を日常導入の要件にしない。非公開のAIアプリ内部パスを固定値として配布しない。
- [ ] 既存のデモと描画部品を再利用し、架空のAGENTS.md / CLAUDE.md・Skillで3モードを試せるようにする。デモから本物の登録・切替操作は呼べない。
- [ ] デモの値は「サンプル」と表示し、実測の改善や製品の性能保証に使わない。比較結果を作成資格として再導入しない。
- [ ] 作者名とHTTPSのサイトURLを設定できる小さなフッターを作る。接続用トークンやローカルの識別情報をリンクへ含めない。操作ボタンの視認性を保つ。
- [ ] `test/web-entry.test.mjs`で未導入・未接続・接続済み・拒否・対応外の各表示と主な操作を検証する。デモ中のローカルAPIへの変更リクエストは0件であることを確認する。
- [ ] 新しいMac環境で導入→「アンハーネスを開いて」→従来の構成をNormalとして保存→解除対象の確認→零式の新規タスクでUNSEAL・TRUEFORMを設計・保存、まで通す。必要な本人操作をそのまま手順に記録し、相談後の構成でNormalを置き換えない。

## オリジナル作品の共有は後続で検討する

2026-09-09に、利用者は共有の仕組みを後で検討してよいとした。ローカルの作成・保存・切替を先に完成させる。初回の共有は[画像カードの保存と投稿準備](../../build-cards.md)までとし、再利用可能な作品パックと公開ギャラリーは後続にする。Mac完成の条件に作品配布サイトを増やさない。

| 段階 | 検討するもの | その前に決めること |
| --- | --- | --- |
| 画像で見せる | 合成したPNG、3モードを並べたカード、作者リンク、任意の比較欄 | 公開する表示名・画像・数値、作者表記、リンク先 |
| パーツを渡す | 本体・拘束具・背景と最小の設定をまとめた作品パックの書き出し / 読み込み | テンプレートの互換性、同梱してよい素材、利用・改変条件、版と作者情報 |
| 見つけて再利用する | ギャラリー、配布ページ、他の人のパーツとの組合せ | 保存先・運用費・投稿確認・管理方法。利用者の別の判断を受けてから設計する |

作品パックは画像と検証済みのデータだけにする。実行コード、Skill本文、ハーネス設定、メモリ、会話、秘密情報、ローカルパスを作品共有へ混ぜない。他人の作品は自動で適用せず、確認・プレビュー・ローカル保存を経る。参照するテンプレートがない場合は互換性を説明し、現在の作品を残す。

## 公開前に必要になる利用者の指定

利用者はSideBizリポジトリを参照したサブドメインの作成を許可した。既存サイトを確認し、`https://unharness.deltahelmlab.com`を公開先、DeltaHelm Labと`https://deltahelmlab.com/`をフッターの表記・リンクに選ぶ。Cloudflare Pagesの既存LPとは別のプロジェクトを使う。DNSと配信は作成後に実際の状態を確認する。公開する配布物とライセンスをレビュー可能に整え、公開や新規契約は具体的な対象を提示してから行う。
