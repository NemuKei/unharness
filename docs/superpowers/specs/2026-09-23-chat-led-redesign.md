# チャット主導への再設計

2026-09-23に利用者と合意した設計。0.0.11 Macプレビューの体験を、非エンジニアが使いやすい形へ組み直す。実装計画は別に作り、この文書は目的・体験・範囲・受入条件を所有する。採用後は [spec.md](../../spec.md)、[product.md](../../product.md)、[spec-workbench-ux.md](../../spec-workbench-ux.md)、[delivery.md](../../delivery.md) を実装と同じ変更で更新する。

## 背景

- 作者は実環境で零式を日常的に使い、困らず、クォータ消費も改善したと感じている。Claude Code側も、自作の指示やSkillをほぼ入れない状態で良好に動いている。価値は「3モードを行き来して比べ続ける」ことより、**外しても大丈夫と安心して確かめられること**で出ている。
- 画面は比較実験の道具として厳密に作られ、内部の状態語・パス・エラーコードが利用者の目に届いている。公開サイトの「AIと進めるデモ」の方が、理想の体験に近い。
- 画面はAIを呼べない（有料API・運用サーバーを使わない約束）。そのためAIへの相談はコピー＆ペーストになっている。

## 原則

1. **対象は非エンジニア。** 画面の言葉は日常語にする。パス・エラーコード・「任意／必須」などの分類語は、普段は表示せず「詳しく」の中に置く。
2. **厳密さは裏側へ。** 保存、入力の一致確認、独立編集の検出、復旧、状態の正直な区別は保持する。画面では「戻せます」「今は切り替えられません（理由）」の粒度で伝える。
3. **判断と推奨はAIが主導する。** 入口はチャット。画面は提案を見て・承認して・戻す場所。
4. **一つの軸で判断する。** 画面・機能は次の4場面のどれに役立つかで置き場所を決める。①初回 ②日常 ③足して試す ④困ったら戻す。
5. **アプリ共通。** 体験・提案・言葉はCodexとClaude Codeで共通にし、差分はadapterが持つ。

## 体験

### 4場面

| 場面 | チャット（AIが主導） | 画面 |
| --- | --- | --- |
| ① 初回 | 「アンハーネスを始めて」→ AIが指示とSkillを読み、外してよいものを分類して提案する | 提案カードに外すもの・残すものを日常語で示し、**[いつもの構成を保存して零式にする]** の1ボタン |
| ② 日常 | 「今どのモード？」「最近どう？」に答える | 今のモードを大きく示し、モード別の使用量の目安を小さく添える |
| ③ 足して試す | 「このSkillを試したい」「モデルを変えた」→ AIが限定解除に足すものを提案する | 提案カード **[足して試す] [やめる]**。一定期間後に「残しますか？」 |
| ④ 困ったら戻す | 「元に戻して」「前の方が良かった」→ すぐ戻し、一言を記録する | 常に見える **[元に戻す]**。AI接続がなくても使える |

### 呼び名

| 役割 | 表示 | 一行説明 |
| --- | --- | --- |
| 日常の既定 | **零式**（TRUEFORM） | 何も足さない、素のAI |
| 日常の選択 | **限定解除**（UNSEAL） | 零式を土台に、選んだ装備だけを解放する |
| 戻る先 | **通常装備**（Normal） | 最初に保存した元の構成 |

零式・限定解除はコンセプト名として残し、名前の直下に一行説明を必ず置く。英語名は装飾として添える。通常装備は日常の選択肢に並べず、[元に戻す] から使う。

初回の零式の既定：登録した追加指示は外し、登録したSkillは「指定したときだけ使う」（manual）にする。AIが外すべきでないと判断したものは提案に含めない。限定解除がまだ無い間は、限定解除のカードは切替ではなく「AIと足すものを相談」へ案内する。

### 普段の画面

```
┌──────────────────────────────────┐
│ [姿（小さめ）]             今：零式            │
│ 最近7日  零式 約120k／タスク  限定解除 約1.3倍  │
├──────────────────────────────────┤
│ ▶ AIからの提案（あれば）    [承認] [やめる]   │
├──────────────────────────────────┤
│ [ 零式 ]  [ 限定解除 ]            [元に戻す]  │
└──────────────────────────────────┘
その他：外観 ・ 詳しい記録 ・ 復旧 ・ 設定
```

- モードのカードを押すと、1枚の確認（「零式にします。外れるもの4件。次の新しいタスクから」）を開き、**[切り替える]** で確定する。表示だけ変わる中間状態を作らない。
- 完了後は「次の新しいタスクから零式です」と **[新しいタスクを始める]** を示す。
- 失敗時は「設定は変わっていません（安全です）」と **[AIに調べてもらう]** だけを示す。詳細な理由・操作IDは「詳しく」に置く。
- スマホ幅では、今のモードと切替ボタンを最初の画面に収める。姿はその下。
- ヘッダーの切替（言語・明暗・演出）は1つの設定メニューにまとめる。

## AIの提案

新しく追加する記録は「提案」だけ。安全装置（計画 → 入力一致の確認 → 適用 → 読み戻し → 復旧）は既存のものを使う。

### 流れ

1. チャットでAIが既存の読み取り（`enrollment_inventory`、`read_mode_contents` 等）で現状を知る。
2. AIが新しいMCP操作 `propose_change` を呼ぶ。Unharnessは既存の計画処理で計画を作り、提案として保存する。
3. 画面は提案をカードで表示する。チャットで「それでお願い」と言っても、画面で [承認] を押しても、同じ既存の `apply_plan` を通る。
4. 結果を画面とチャットの両方へ返す。

### 提案の中身

- 種類：`initial` / `add` / `remove` / `restore`
- 対象ごとの日常語の理由（AIが書く。例：「作業手順を細かく指示するSkillです。新しいモデルでは不要なことが多いです」）
- 裏側の計画IDと、元になったsourceのhash
- 状態：承認待ち / 適用済み / やめた / 古くなった
- 新しい提案が出たら、同じ対象の古い承認待ち提案は「古くなった」にする。

### 安全の約束の言い換え

- **初回の分類**：現在は利用者が「自分が追加した任意の設定です」とチェックで宣言している。これを「AIは、これらはあなたが追加したもので、外しても仕事の決まりには影響しないと判断しました」の表示と **[OK]** に置き換える。利用者の承認が必要という原則は変えず、分類の作業をAIへ移す。必須と任意が混ざる指示は、AIが外す対象に含めない。
- **古くなった提案**：提案後にsourceが変わっていたら承認を無効にし、「状況が変わりました。AIにもう一度聞いてください」と示す（既存の入力一致確認を使う）。
- **判断基準**：同梱の管理Skill本文に書く。Unharness自体はモデルを呼ばない。

### 声かけ

画面側の決まったルールで出す。限定解除に足してから3日、またはその構成で新しいタスク5件のうち早い方で「○○を足して3日経ちました。残しますか？ [残す] [外す] [AIに相談]」を示す。使用量の変化を自動で添える。評価が必要なときだけAIへ聞く。

### 使用量の目安

- 既存のタスク記録から、モード別に最近7日を都度集計する。新しい永続形式は作らない。
- 画面は同じアプリ内の相対比較（「零式に比べて約1.3倍」）を主にし、絶対値は「詳しく」に置く。仕事の内容が違うため、性能差や因果を主張しない。
- Codexは記録された合計token、Claude Codeは記録された構成要素を同じ基準で合算せずに扱い、アプリ間では比べない。合計が記録されない場合、推定の合計を作らない。

| 区分 | 対象 |

## Claude Code対応

体験・提案・言葉は共通。adapterが持つ差分は次のとおり。

| 項目 | Codex | Claude Code |
| --- | --- | --- |
| 追加指示 | base `AGENTS.md` は保持し、`AGENTS.override.md` で切り替える | 単一の `~/.claude/CLAUDE.md` を直接書き換える。零式では中身のない内容で存在を保つ |
| Skillの自動使用 | `skills.config` と `agents/openai.yaml` | `settings.json` の `skillOverrides` |
| 使用量 | 記録された合計token | requestごとの構成要素。合計は記録されない |
| 管理の入口 | 同梱の管理Skill・MCP | 同じ役割のSkill・MCPをClaude Codeへ導入する |

Claude側の指示ファイルは一つしかないため、Unharness以外がそのファイルを書くと直接衝突する。個人の配布用repoなど他の仕組みは、Claude Codeの `CLAUDE.md` とSkillの自動使用の可否を書かない前提にする（その変更は別repoで扱う）。Skillの自動使用の制御は `skillOverrides` の一層だけにする。

## データと移行

- v1〜v4の保存構成、お気に入り、evidenceは書き換えない。
- 追加する保存形式は「提案」だけ。既存形式を変えない。
- 退役した機能のデータファイルは削除しない。閲覧画面は作らず、必要時はAIが読む。
- 既存の限定解除（UNSEAL）の保存内容は、そのまま「限定解除」として表示する。意味の変更はない。

## 検証

- 既存の `npm run check`、`npm run build`、`node --test` を通す。
- 画面は合成HOMEで確認する：`HOME` と `CODEX_HOME` を一時directoryへ向け、`gui --manage-sources` を起動する。個人の `~/.codex`・`~/.agents/skills`・`~/.claude` を開発中の画面へ向けない。macOSの `/private/tmp` 配下はgroupが `wheel` になり所有者確認で対象外になるため、合成ファイルは `chgrp -R staff` する。
- デスクトップ幅と375px幅の両方で、4場面を実際に操作する。
- 最後に利用者の実機で、導入・零式・限定解除・元に戻す・AIなしの復旧を確認する。

## 受入条件

1. 未登録の状態から、チャットで「アンハーネスを始めて」と頼み、画面の [OK] と1ボタンで、通常装備の保存と零式の準備まで進める。パス・エラーコード・分類語を見ずに完了できる。
2. 普段の画面の最初の表示に、今のモード、零式／限定解除の切替、[元に戻す]、使用量の目安がある（375px幅でも）。
3. チャットと画面のどちらで承認しても、同じ計画が同じ適用処理を通る。提案後にsourceが変わると承認できない。
4. 失敗時の画面は、安全であることと [AIに調べてもらう] だけを示す。
5. AI接続がなくても、画面から元に戻せる。
6. 退役A・Bの操作経路が画面・MCP・公開サイトから消え、過去のデータファイルは残る。
7. 0.2.0で、同じ1〜5がMac Claude Codeで成り立つ。

## 範囲外

- 複数モードへの同時実行、自動の最適構成の選定、構成の共有マーケット。
- 公式プラグインの個別OFF（Codexの制約。従来どおり保持）。
- アプリ間の使用量の比較。
