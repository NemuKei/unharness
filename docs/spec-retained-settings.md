# Retained setting changes

This extends the registered user-source contract so an independently changed Codex setting can be kept across the next mode preparation. It is part of the approved Mac completion goal, not permission to choose new optional source roles.

## User behavior

An independent edit still produces a conflict. The workbench offers **変更を確認** when no recovery is pending. A read-only review may establish that only retained configuration changed. Its summary names categories, never configuration values, and explains that the current Codex settings will be recorded, the selected instructions/Skills will stay as registered, and old saved versions will remain available. **現在の設定を引き継ぐ** accepts that exact plan. This records a new Normal version without writing a managed configuration file.

Normal, UNSEAL and TRUEFORM subsequently compile from that active Normal. An independent retained edit can be reconciled in any of those three states, including a state obtained from a favorite or checkpoint. The selected source contents, invocation policies and selected configuration entries must still match the previously prepared state. Changed source roles, Skill bodies, managed sources, selected enablement, unsupported metadata, redirected parents, or ambiguous overlap remain conflicts requiring separate review.

Old favorite/checkpoint records and their snapshots are immutable. Within the same Normal version, restoration remains exact. Across Normal versions, a restore plan explicitly says it will keep the current retained settings and use the saved selected source state. It has a new snapshot identity and an `adaptation` summary, and is not represented as the original favorite's exact configuration. Preparing that plan does not silently save a replacement favorite. The normal save action can save the new version. Older checkpoint plans also preserve current retained settings.

## Configuration composition

Use a single private helper, `mergeRetainedConfig({ baseText, targetText, currentText, skillPaths, executable, executableArgs?, timeoutMs? })`. The base is the shared ancestor; target contains the desired selected Skill state; current contains the retained settings to preserve. For reconciliation, these are the expected prepared configuration, the active saved Normal configuration, and the actual configuration. For an old favorite, they are that favorite's Normal, its frozen configuration, and the active Normal.

The helper returns `{ text, changed, codexVersion }`. It has no destination path and cannot write the user's files. Native parsing is confined to freshly created private profiles and allows only initialization and `config/read`. The complete parsed user layer stays inside the helper. The existing `readSkillSelectors` public projection stays unchanged. No task/model, MCP operation, hook command, or arbitrary native write may be invoked.

Validate that target differs from base only in registered selected `skills.config` entries, and that current retains the base's complete selected entries, including duplicates and extra metadata. Compare retained configuration after removing selected entries; preserve unselected entries and their relative order, all other `skills` fields and every other parsed user-layer value. Empty Skill containers introduced solely by selected controls may normalize to absence. Reject invalid selector shapes, version disagreement and numeric values whose native JSON representation cannot prove equality.

Compose exact line buffers with locked `node-diff3` 3.1.2; it declares Node support and requires no runtime dependency. Preserve line terminators and final-newline state. Refuse any conflict, rather than choosing a side or emitting markers. The result must parse, have exactly the target's complete selected entries, and exactly the current retained configuration. No TOML serialization, regex key rewriting, whitespace normalization or Git executable is part of this operation. Bound inputs to 128 KiB each and 4096 lines each to bound synchronous merge work. An unchanged target or current can take the exact-byte path after the same native validation. Comments remain literal lines; overlapping edits that cannot be separated remain unavailable.

## Versioned records

Keep `registration.normalId` as the immutable registration baseline used for source-role and body identities. Add optional `state.normalId` for the active Normal snapshot; legacy state defaults to the registration baseline. Active Normal snapshots must have the same non-config files as the registration baseline. New mode plans, favorites and checkpoints record their Normal ID; legacy records default to the registration baseline. A state revision change invalidates old plans. Existing task observations are dated history, and accepting retained settings clears the current observation and creates a new preparation boundary without upgrading any verification flag.

`planUserRetainedSettings({workspace})` checks bindings/current source captures, pending recovery, and the native composition proof. It persists a `retained-plan` application record with scope/revision, previous snapshot/Normal IDs, actual observed snapshot ID and new Normal ID. It returns IDs, the current prepared mode, fixed safe category labels, `managedFilesChanged: 0`, retained conditions and the existing false verification flags. It must not expose arbitrary key names, paths, raw text, values or native diagnostics. A byte/metadata no-op reports `no-retained-change`.

`acceptUserRetainedSettings({workspace,planId})` reopens the workspace under the existing exclusive profile lock, validates the exact plan, checks the previous revision/Normal/snapshot and rechecks every actual observed file and parent immediately before publication. Only private records/state change. Preserve the existing selected scope and owned directory identities. Record `lastRetainedPlanId` for idempotence and clear `lastPlanId`; a duplicate returns the same result only while its resulting state is still current. Later independent edits block that duplicate. The current preparation mode stays the same.

Use the existing pending-file boundary with a distinct retained-recording journal kind, holding a validated before state and accepted plan. Publish the journal before the atomic state change, then clear it at the committed boundary. The Node-only recovery dispatcher recognizes it without loading Codex, YAML or diff3. Recovery cancels an interrupted retained-recording operation by restoring its prior private state and removing only its known journal; it never changes any managed source. Subsequent status can truthfully show the still-existing external configuration conflict. Do not erase foreign temporary files or replace another operation's state. A completed later operation must never be rolled back by a stale retained journal.

Ordinary preparation journals/checkpoints carry the active Normal identity so interruption recovery cannot revert the retained context by omission. Favor exact frozen bytes for all actual managed-file publication and offline recovery. Cross-version adaptation happens only while planning; an approved plan can be applied and recovered without the compiler.

## UI and CLI

Add CLI `sources plan-retained` and `sources accept-retained`. Both use structured arguments and the same service as the workbench. Browser routes receive only a plan ID and the already accepted launch/workspace identity. Existing Host/origin/token, request-id deduplication, stale context, refresh-before-action and unknown-mutation-outcome protections remain in force.

Conflict review and its accept action stay inside the existing state/control area, not another mode. Ordinary mode controls stay unavailable while a conflict exists. Show an explicit review summary before accept. Disable review during pending recovery. Clear all cached preparation/reconciliation plans when scope, accepted launch, revision or active Normal changes. Never auto-accept on refresh/reconnect or retry an uncertain mutation. On success reload state/favorites; keep recovery usable after errors. An adapted favorite/checkpoint plan states **現在の共通設定を維持して準備** and identifies that saving creates a new version.

## Verification

- Synthetic helper tests cover changes to model/speed/memory/native continuity/permissions and unselected Skill entries, comments, CRLF, final newline, duplicates, original absent entries, invalid TOML, selected changes, overlapping edits, native version/layer errors, bounded input and secret-free errors. Verify read-only RPC methods and private-profile cleanup.
- Service tests run an independent retained edit in Normal, UNSEAL and TRUEFORM, accept without changing any managed bytes/metadata, then prepare all modes and restore Normal while keeping that edit. Cover repeated Normal versions, exact legacy favorites, explicit old-favorite and old-checkpoint adaptation, old record immutability, current observation invalidation and no inferred source selection.
- Negative and recovery tests cover non-config edits, selected config edits, links/ownership, stale/deduplicated/concurrent calls, after-review changes, pending interruption before/after state publication, no-clobber cancellation and frozen-plan/offline recovery without the compiler.
- HTTP and UI tests cover accepted context, duplicate request payloads, uncertain outcomes, plan invalidation, conflict review, adaptation notice and recovery access. Run type/CSP/build and the built workbench in a browser, including narrow layout and a second client changing state.
- Run native Mac tests with an owned profile first. A real-profile review is read-only until the exact current change and plan are presented for the user's decision. Never use an old backup to overwrite the user's current retained settings.

This is configuration versioning and persisted preparation evidence. It does not prove a desktop task has loaded the new state or complete the Mac product goal.
