# 初期設定と日常操作の画面

> **2026-09-24に置き換え：** 普段の画面・提案・呼び名は[チャット主導への再設計](superpowers/specs/2026-09-23-chat-led-redesign.md)に従う。公開サイトからの操作と再実行は退役した。以下は0.0.11の画面の契約として残す。

日常操作はローカルGUIにまとめる。公開サイトは紹介・デモ・導入・更新案内を担う。[ローカル入口の仕様](spec-local-entry.md)が2026-09-14以前の公開操作中心の旅程を置き換える。実際の状態変更は既存の登録・計画・実行・復旧処理を使い、過去の公開操作の結果と限定された互換経路を残す。

## 入口と役割

- 初期設定・設定変更・モード切替・外観という機能は共通で、画面から操作する入口とチャットで依頼する入口を持つ。紹介と各操作の近くに、導入後に使える短い依頼例を示す。チャットを「GUIの操作説明を聞く場所」だけにしない。
- 接続済み画面からコピーする依頼には、確認済みの登録範囲IDを付ける。AIは最新のstatusとの一致を確認し、違う接続で進めない。公開紹介の一般的な例では範囲を推測しない。ローカルパスや設定本文を依頼へ含めない。
- 登録済みのモード切替は管理Skill/MCPが計画・適用を実行し、同じ保存状態を画面へ反映する。切替時はアプリ内ブラウザでモードの表示を確認できるよう案内する。画面や演出を開けなくても、設定操作の結果とは区別する。初回の対象確認・接続許可まで完全自動と約束しない。
- 2026-09-20の追加判断で、普段の画面はモード選択と選んだ構成の内容に絞る。記録・比較、外観、設定、接続・復旧は「その他」から開く。初期設定は未登録と確認できたときに「設定」で案内する。未接続・未確認を未登録と推測しない。
- 初回は「初期設定をAIに頼む」、登録後は「設定をAIと見直す」。クリックで依頼文をコピーし、Codexに貼り付けて送る手順を近くに示す。初回の対象確認とNormal保存は、このMacの確認画面で行う。コピーや相談だけで設定済みと表示しない。
- 管理Skillでローカル画面を開き、その画面で操作を完結する。日常操作に公開接続の作成や許可を求めない。以前の操作結果の照会は補助画面に残す。
- 仕事の記録は「その他 → 記録・比較」へ置き、名前で選んで記録し、1件で振り返り、2件から比較する。[記録UX](spec-work-record-ux.md)に従い、UUID・詳細評価・再実行は必要なときだけ開く。お気に入り、復旧・過去の公開結果は補助画面へ。競合や復旧待ちはモード操作の近くにも出す。

## モードの内容を見る

普段はNormal・限定解除・零式の選択と、選んだモードの保存内容を縦に置く。構成のあるモード名を押す操作は表示だけを変え、設定の準備や計画作成をしない。切替は別の「変更内容を確認 → この内容で確定する」で行う。旧設定の対象調整経路は互換性のため保持する。

内容は「追加指示」と「切替対象のSkills」。追加指示は保存したAGENTS.md、保存した最小ガイド、v4で保存した追加指示、追加指示なし、登録対象外の保持を区別する。Skillは自動で選べる・指定時のみ・使わない・未確認で件数と名前を示し、多い区分は数件と残りを開く入口を見せる。指示とSkillの本文は明示してローカルで開く。AI要約や現在のファイルを保存版の代わりにしない。カスタム本文の作成・変更はAI相談で行い、通常画面には大きな編集欄を追加しない。

プロジェクト指示・メモリ・権限・管理機能が残ることは短い一文で常時示す。準備済みのモードと表示中の構成を分け、Normalには解除設定の未準備表示を流用しない。独立編集で切替が停止しても、保存内容の閲覧は継続する。閲覧はモード選択を無効化しない。外観はモード選択の上に常時表示し、選んだモードに連動させる。画像の表示や演出は設定の適用とは区別する。

`mode-contents` は固定された登録範囲の保存構成だけを返す。`mode-source` はその結果のモード・snapshotId・sourceIdに対応した本文だけを返し、別のパスや古い選択を受け付けない。ネイティブの再探索、構成の再保存、モデル起動を行わない。アプリ固有の読み方はCodexアダプターに置き、Claudeの対応を推測しない。

## モード切替

選択ボタン、次のタスク向けの変更内容、確定ボタンを同じ領域に置く。選択・変更計画だけでは設定を変えない。確認後の「この内容で確定する」が既存の適用処理を呼ぶ。ローカルの選択時の計画取得と、公開側の計画確認は、それぞれの既存処理を保つ。

2026-09-14の見直しでは、表示設定などモード対象以外の変更は切替計画の中で確認し、そのまま引き継ぐ。利用者に差分の分類やNormal版の更新を別途判断させない。共通設定だけの変更と証明できた場合に限り、通常のモード確定に含める。確認後の別編集、指示・Skillの変更、復旧待ちは引き続き停止する。保存状態に差分がある間は「最後に準備したモード」と表示し、画面を開く・選ぶ・再接続するだけでは保存状態を更新しない。

押せない操作には理由と解消する入口を添える。

| 状態 | 近くに置く入口 |
| --- | --- |
| 状態未確認 | 状態を再取得 |
| 未登録 | 初期設定へ |
| 2構成の確認・保存待ち | 設定をAIと見直す |
| 指示・Skillの変更、または共通設定だけと確認できない差分 | このMacで差分を確認／状態の確認をAIに頼む |
| 中断・復旧待ち | このMacで復旧する |
| 操作結果が不明 | 元の操作IDで結果を確認する |
| 処理中 | 完了を待つ理由を表示。重複操作は止める |

相談のコピーは設定を書かない。競合や中断時にも使えるようにし、その場合の依頼は状態・復旧の確認へ切り替える。未確認の操作を新しいIDで再実行したり、保存したNormalを無断で更新したりする依頼にしない。

完了は「次のタスク用の準備ができた」と表示する。実行中タスクの反映や、表示した外観からの性能向上を主張しない。

## 指示の範囲

Codexの紹介・デモは「グローバルAGENTS.md（共通の追加指示）」と具体的に示す。実際には、選択して登録した任意のグローバル指示の読み込ませ方を切り替える。元のAGENTS.mdとリポジトリのAGENTS.mdは保持し、切替先のAGENTS.override.mdの扱いは詳細に示す。

リポジトリのファイルを変更しないことと、そのプロジェクトの動作に影響しないことは別である。同じCodex設定を使う他のプロジェクトの新しいタスクにも共通する変更であることを対象確認時に示す。Claudeの既存アダプターではそのアプリの指示名を使い、Codexのファイル方式を流用して説明しない。

## 検証

1. 未登録・登録済み・構成確認待ち・競合・中断・接続切れの各状態で、次に押す場所が分かる。
2. 相談コピー、タブ移動、プレビューでは設定を書かない。確定時だけ既存の適用処理を使う。
3. 競合時の相談文は確認用に限定され、モード適用は止まる。独立編集、履歴、復旧条件を保つ。
4. 公開接続の期限・元IDでの結果照会・重複停止と、ローカルでの独立復旧を保つ。
5. 画面幅が狭くても選択・理由・解消する操作・確定が離れず、キーボードで操作できる。

実装は、共通のナビゲーション・操作理由の表示、ローカル画面の再配置、公開画面の再配置、説明と既存ブラウザ検証の更新の順で行う。個人設定でのモード操作や配布物・公開サイトの更新は、この画面実装の検証から独立して扱う。
