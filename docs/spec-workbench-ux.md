# 初期設定と日常操作の画面

公開・ローカル両方の操作画面を、利用者の「初期設定・設定変更・モード切替・外観」の目的から組み直す。実際の状態変更は既存の登録・計画・実行・復旧処理を使い、公開接続の権限や保存形式は拡張しない。

## 入口と役割

- 初期設定・設定変更・モード切替・外観という機能は共通で、画面から操作する入口とチャットで依頼する入口を持つ。紹介と各操作の近くに、導入後に使える短い依頼例を示す。チャットを「GUIの操作説明を聞く場所」だけにしない。
- 接続済み画面からコピーする依頼には、確認済みの登録範囲IDを付ける。AIは最新のstatusとの一致を確認し、違う接続で進めない。公開紹介の一般的な例では範囲を推測しない。ローカルパスや設定本文を依頼へ含めない。
- 登録済みのモード切替は管理Skill/MCPが計画・適用を実行し、同じ保存状態を画面へ反映する。切替時はアプリ内ブラウザでモードの表示を確認できるよう案内する。画面や演出を開けなくても、設定操作の結果とは区別する。初回の対象確認・接続許可まで完全自動と約束しない。
- 普段のナビゲーションは「モード・設定・外観」。初期設定は未登録と確認できたときに「設定」で案内する。未接続・未確認を未登録と推測しない。
- 初回は「初期設定をAIに頼む」、登録後は「設定をAIと見直す」。クリックで依頼文をコピーし、Codexに貼り付けて送る手順を近くに示す。初回の対象確認とNormal保存は、このMacの確認画面で行う。コピーや相談だけで設定済みと表示しない。
- 公開側が普段の入口、ローカル側が接続許可・対象確認・復旧とオフライン時の操作を担う。同じ操作名を使い、「このMacで差分を確認する」など目的を示して移動する。ローカルでの操作は公開接続を必須にしない。
- 比較・保存履歴・接続・復旧・検証記録は補助の入口へ。競合や復旧待ちはモード操作の近くにも出し、補助画面へ探しに行かせない。

## モード切替

選択ボタン、次のタスク向けの変更内容、確定ボタンを同じ領域に置く。選択・変更計画だけでは設定を変えない。確認後の「この内容で確定する」が既存の適用処理を呼ぶ。ローカルの選択時の計画取得と、公開側の計画確認は、それぞれの既存処理を保つ。

押せない操作には理由と解消する入口を添える。

| 状態 | 近くに置く入口 |
| --- | --- |
| 状態未確認 | 状態を再取得 |
| 未登録 | 初期設定へ |
| 2構成の確認・保存待ち | 設定をAIと見直す |
| 保存時と異なる設定 | このMacで差分を確認／状態の確認をAIに頼む |
| 中断・復旧待ち | このMacで復旧する |
| 操作結果が不明 | 元の操作IDで結果を確認する |
| 処理中 | 完了を待つ理由を表示。重複操作は止める |

相談のコピーは設定を書かない。競合や中断時にも使えるようにし、その場合の依頼は状態・復旧の確認へ切り替える。未確認の操作を新しいIDで再実行したり、保存したNormalを無断で更新したりする依頼にしない。

完了は「次のタスク用の準備ができた」と表示する。実行中タスクの反映や、表示した外観からの性能向上を主張しない。

## 指示の範囲

Codexの紹介・デモは「グローバルAGENTS.md（共通の追加指示）」と具体的に示す。実際には、選択して登録した任意のグローバル指示の読み込ませ方を切り替える。元のAGENTS.mdとリポジトリのAGENTS.mdは保持し、切替先のAGENTS.override.mdの扱いは詳細に示す。

リポジトリのファイルを変更しないことと、そのプロジェクトの動作に影響しないことは別である。同じCodex設定を使う他のプロジェクトの新しいタスクにも共通する変更であることを対象確認時に示す。Claudeの既存アダプターではそのアプリの指示名を使い、Codexのファイル方式を流用して説明しない。

## 検証

1. 未登録・登録済み・構成確認待ち・競合・中断・接続切れの各状態で、次に押す場所が分かる。
2. 相談コピー、タブ移動、プレビューでは設定を書かない。確定時だけ既存の適用処理を使う。
3. 競合時の相談文は確認用に限定され、モード適用は止まる。独立編集、履歴、復旧条件を保つ。
4. 公開接続の期限・元IDでの結果照会・重複停止と、ローカルでの独立復旧を保つ。
5. 画面幅が狭くても選択・理由・解消する操作・確定が離れず、キーボードで操作できる。

実装は、共通のナビゲーション・操作理由の表示、ローカル画面の再配置、公開画面の再配置、説明と既存ブラウザ検証の更新の順で行う。個人設定でのモード操作や配布物・公開サイトの更新は、この画面実装の検証から独立して扱う。
