# Guided product entry

The production UI shares the reviewed [Codex draft handoff](guided-entry-preview.md)
and guided sample experience with the concept. The entry offers GitHub,
Japanese/English, a Codex startup draft and a copy fallback. Opening a draft does
not send a task or establish installation success. The original user-confirmed
Mac prefill remains scoped to that observation; a published HTTPS handoff needs
its own check.

The introduction, installation, synthetic demos and ordinary registered workbench
support both languages, including source review, mode confirmation, appearances,
comparisons and local recovery. A language change preserves the current page,
selected mode, reviewed plan and entered artwork brief. User-authored names,
source contents, saved records and task output are never translated or rewritten.
The local language preference is separate from all loadout state. The new local
entry accepts exactly `?lang=ja` or `?lang=en` on `/`; other asset/API query rules
remain unchanged. Successful v2 redemption advertises `X-Unharness-UI-Languages:
ja,en` as display-only response metadata, without changing JSON contracts. The
public client adds the language query only for that current connection. Earlier
servers keep their original fragment navigation and installed UI language. Developer-only
owned-fixture diagnostics retain their existing Japanese interface.

The AI-guided demo is marked as synthetic throughout. Its sample versions,
Normal saving and update steps are illustrative. It has no configuration
controller and cannot install or update a plugin. The real connected workbench
continues through the existing PublicConnection, local approval and WebMCP
operations. A demo does not become evidence of a user's prepared mode.

## General startup

The installed management Skill checks actual state and the fixed public release
catalog, explains a useful update and lets the user update or continue. It then
guides missing connection, initial target review/Normal saving, recovery or a
saved-pair consultation, as applicable. Ready users receive one useful next
step. Concrete mode, recovery and artwork requests keep their direct operation
path. Optional Skill-content review remains separate.

See [plugin updates](plugin-update.md) for the version evidence, network bounds,
native-source replacement and fresh-task checks. The implementation provides
read-only update discovery and an AI-guided native procedure; it is not a
background updater. Deferring an update avoids the same offer in that
conversation and is not a persisted cross-task preference.

## Release record

`site/public/releases/macos-arm64.json` is the canonical published Mac release
record. The static build validates it and the download card derives from it.
The native `check_updates` reads the deployed copy without private request data.
Do not move this record to a new version until that exact public ZIP, SHA256,
distribution ID and source revision have been verified. A source or package
version bump does not itself update the published record.

The implementation's build/browser evidence and the subsequent archive or public
checks belong in [the dated evidence](evidence/2026-09-14-guided-product.md).
