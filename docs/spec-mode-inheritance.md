# 零式の公式プラグインと限定解除への継承

2026-09-10採用。**Docs上の新しい契約であり、実装・移行・実機検証は未完了。** [製品仕様](spec.md)と[設定相談](spec-guided-setup.md)のモード選択を具体化する。実装順は[専用計画](superpowers/plans/2026-09-10-official-plugin-mode-inheritance.md)に従う。以前の設定・検証記録は、その時点の契約として保持する。

## 目的

零式で比較の基準を決め、限定解除で必要な手順だけを足す。零式が常に優れる、公式掲載なら軽い・安全・高性能、といった保証はしない。Normalを維持する判断も有効な結果にする。

| モード | 任意の追加指示 | 自動使用を残せるSkill |
| --- | --- | --- |
| Normal | 保存した元の内容 | 保存した元の状態 |
| 零式 — TRUEFORM | 選択した任意の追加指示なし | 対応するAIの公式マーケットプレイス由来と確認できたプラグインから、利用者が選択したもの |
| 限定解除 — UNSEAL | 保存した最小ガイド、または追加指示なし | 零式で残したものをすべて継承し、任意の外部Skill・自作Skillを追加できる |

この表の「残す」はSkillの自動使用を残すこと。「外す」は、制御可能な登録済みの有効なSkillを明示呼び出しのみにすること。インストール削除、Skill本文の削除、プラグイン全体の無効化とは異なる。Normalで無効なSkillは、別の明示的な有効化なしにONへ変えない。Normalで手動のみの項目を自動へ変える場合も、変更をレビューに示す。

メモリ、標準の作業継続、権限、管理ポリシー、必須のプロジェクト要件、標準提供の条件は共通で保持する。**正式に登録されたUnharnessの管理Skillと起動・状態確認・切替・復旧接続は、公式掲載前でも共通保持する例外。** 名前の一致やファイルの自己申告では例外にしない。任意の制作・相談Skillにこの例外を広げない。

## 必ず守る関係

登録済みで制御可能な任意のSkillについて、次の二つだけを選択の入力にする。

- `Z`: 零式で残す公式プラグインの、確認済みの対象Skill集合。
- `A`: 限定解除だけで追加する外部Skill・自作Skill集合。

```text
零式の自動使用対象 = Z
限定解除の自動使用対象 = Z ∪ A
Z ⊆ 限定解除の自動使用対象
```

共通保持する管理機能等はこの任意集合の外に置き、両モードに同じ状態で加える。集合は実際の有効状態を反映する。重複したSkillを二重計上しない。外部／自作という由来の確認と、公式掲載の確認は別に扱う。

限定解除に独立した「全自動対象一覧」を入力させて零式との不一致を許す設計にはしない。GUI・CLI・MCP・読み戻しが同じ合成規則を使う。限定解除だけで継承項目を外す要求は拒否し、零式側の変更へ案内する。Normalは保存した元の構成であり、`TRUEFORM ⊆ UNSEAL ⊆ Normal`は約束しない。

## 公式マーケットプレイス由来の確認

初回の実装対象はMac Codex。ここでいう公式は、ホスト提供者が運営する公開プラグインディレクトリを指す。そこに掲載された第三者製プラグインも候補になり得る。「OpenAIが制作したものだけ」とはしない。一方、個人用・組織用・プロジェクト用マーケットプレイス、直接追加したGitリポジトリやローカルコピーは、同じ画面に表示されてもそれだけでは公式扱いしない。

ホスト側で確認できる掲載元と導入記録から、公式掲載の識別子、導入済みプラグインの識別子、配布元、版またはリビジョン、対象Skillの識別子と内容の版、確認日時を結び付ける。正確な取得方法は、実際のCodexの一次資料と読み取り専用の実機調査で確認する。取得できない項目を推測で埋めず、名前・パス・`user` scope・`pluginId`の存在・AIや利用者の自己申告だけで公式と認定しない。

確認結果は「公式由来を確認」「公式対象外」「未確認」を区別する。未確認のものは零式の残す候補に入れず、説明を出す。任意性・所有範囲・手動化能力が別途確認できれば、限定解除への追加候補にはできる。確認できないからといって既存の個人設定を勝手に無効化・削除しない。

公式のすべてを自動選択しない。零式の選択は空でもよい。対応する別アプリの公式掲載元をCodexから推定しない。Claudeの対応と確認は既存の後続計画に置く。

## プラグインを選び、変更するSkillを確認する

画面やAI相談ではプラグイン単位で選択できるようにする。ただし保存時には、現在の登録範囲内にある変更対象のSkillへ展開し、その一覧を固定する。プラグイン内のSkillが未登録なら、先に既存の確認付き追加登録を使う。プラグインの選択だけで登録範囲を広げない。一部のSkillだけが対象なら、その範囲と残る項目を明示し、プラグイン全体を制御したと表示しない。

Skillの自動使用、MCPや外部サービスの接続、hook、権限を別の能力として確認する。手動化のために接続や権限を変えない。ホストがプラグイン全体のON/OFFしか提供しない場合、その制御を手動化の代用品にしない。提供元のキャッシュを書き換えて未対応の制御を作ったことにしない。未対応範囲が必要な構成は準備を止め、現在の状態と復旧経路を残す。

零式で残さない登録済み任意Skillには、公式由来でも自作でも、対応する明示呼び出しのみの扱いを適用する。未登録・必須・制御不能な残存要素は別表示し、「AI全体から追加指示が消えた」「完全に素のモデル」とは説明しない。

## 保存、変更、履歴

零式と限定解除を一つの確認済み設定版として保存する。零式から引き継ぐ対象と限定解除だけの追加対象、公式由来の確認版、展開した対象一覧、規則の版を保持する。保存・採用は記録の操作であり、設定ファイルや実行中のタスクを変更しない。適用は既存の計画確認・準備操作で行う。

零式の選択を変えるときは、限定解除への影響も同じレビューに出す。零式から外した項目を限定解除だけに残すには、そのレビューで追加対象へ明示的に移す。選択を戻しただけで以前の追加判断を推測・復活させない。零式で選んだ項目は継承に一本化し、追加対象との重複を残さない。

新しい設定版を保存しても、以前のお気に入り・比較・Normal・復旧点を書き換えない。過去のお気に入りは、その時点の規則と構成として復帰する。現在の零式を過去のお気に入りへ注入しない。最新規則へ移す場合は、利用者が確認した別の新しい版を作る。

プラグイン更新、掲載元変更、ローカル変更、新しいSkillの追加で、過去の確認を別内容へ流用しない。差分を示し、新しい確認と保存版を要求する。公式掲載の確認のためだけに、通常の切替ごとにオンライン照会を必須にしない。保存済みの確認と内容の一致が使える範囲を日時付きで示し、確認できない新しい構成は保留する。現在の設定や歴史的な観測を書き換えず、オフラインのNormal復帰を妨げない。

既存のv1設定は、外部Skillの独立した選択を持つ旧規則として読み取り・復帰可能にする。公式由来の確認なしに新規則へ昇格しない。新しい規則は明示した形式・版で保存し、未対応の旧プログラムからの書き込みを拒否する。個人設定を移行する前に、中断復旧と独立編集の保持を検証する。

## 画面とAIへの説明

通常画面は三モードを中心に保ち、詳細な選択は既存の「設定をAIに相談」で扱う。確認画面では「零式から引き継ぐもの」と「限定解除で追加するもの」を分け、継承側は限定解除内で編集できない表示にする。公式未確認・手動化未対応・未登録の理由を省略しない。

例として「追加指示なし／Skillは自動2件・手動8件／メモリと管理機能は維持」と表示できる。数値は保存版と登録範囲に基づき、無効・未確認の項目を自動や手動に数えない。モデル全体の読み込みを保証する数字ではない。

零式は「選択した公式プラグインを残した基準構成」、限定解除は「零式に必要な手順を足した構成」と説明する。切替後は「新しいタスク向けに準備済み」と、その後の特定タスクで確認できた状態を分ける。グローバル設定の変更は同じCodex環境の今後のタスクへ共通して影響することも表示する。

## 受入れ条件

1. 公式由来の確認済み候補だけを零式で選択でき、未確認・私設マーケット・ローカルコピー・名前の偽装で回避できない。
2. 零式が空の場合、一つの場合、複数の場合で、限定解除が必ずその全対象を含む。直接のCLI/MCP入力や保存記録の不正な組合せでも逆転を許さない。
3. 限定解除だけに任意の外部Skill・自作Skillを追加できる。明示呼び出しと無効状態を守り、MCP・hook・権限を巻き込まない。
4. 公式未掲載のUnharness管理機能を全モードで保持し、他のSkillが同名を名乗っても例外にならない。
5. 両モードの新しい版を保存しても、現在の準備状態、Normal、過去のお気に入り、比較、復旧点は変わらない。旧版復帰、追加登録、更新、中断、独立編集を確認する。
6. GUI・CLI・MCPで同じ対象と版を得る。Mac Codexの新規タスクで自動使用の有無と明示呼び出しを確認し、Normalへ復帰する。準備だけの証拠で新規則の実機対応を宣言しない。

## 一次資料と確認範囲

2026-09-10に確認した資料。文書上の仕組みとUnharnessの実機対応は別である。

- [OpenAI: Package your plugin](https://developers.openai.com/plugins/build/plugins): 公開ディレクトリとローカル・リポジトリのマーケットプレイスの区別、Skill・MCP・hook等の構成。
- [OpenAI: Submit plugins](https://developers.openai.com/plugins/deploy/submission): 開発者が申請する公開の仕組み。公式掲載と提供者自身による制作を同一視しない。
- [OpenAI: Build skills](https://learn.chatgpt.com/docs/build-skills): Skillの自動使用と明示的な呼び出し。導入形式ごとの安全な制御方法は実機調査で確定する。
