# Skillの3段階と公式プラグインの継承

2026-09-11採用。通常Skillを「無効・手動・自動」、プラグインを「Normalの状態を保つ・全体を無効」に分けるv3契約。**実装と実機検証は進行中。** [v2の契約](spec-mode-inheritance-v2.md)と既存の保存記録は以前の意味で保持する。[実装計画](superpowers/plans/2026-09-11-source-state-v3.md)に従う。

## 利用者が選ぶもの

通常画面はNormal・零式・限定解除の三モードを中心に保つ。細かな選択は各解除モードの詳細と「設定をAIに相談」に置く。通常Skillはプラグイン管理外の自作・外部導入Skillを指す。由来だけで制御方法や任意性を推定しない。

| 対象 | 零式 — TRUEFORM | 限定解除 — UNSEAL |
| --- | --- | --- |
| 選択した任意の追加指示 | 追加指示なし | 追加指示なし、または固定した最小ガイド |
| 登録済みの任意の通常Skill | 各Skillを無効・手動から選ぶ | 零式を継承し、無効から手動・自動、手動から自動へ追加できる |
| 登録済みの任意のプラグイン | 公式掲載を確認したものからNormal状態を保つ対象を選ぶ。それ以外の登録対象は全体を無効 | 零式で保つ対象を継承し、登録済みの追加対象をNormal状態へ戻せる |
| Normal | 保存した元の指示・Skill・プラグイン設定を復帰 | 同左 |

「無効」はホストのSkill選択から外す状態、「手動」は明示的に指定して使う状態、「自動」は依頼に応じてAIが選べる状態。ファイル自体の削除や読取権限の変更は行わない。Normalで無効な通常Skillを手動・自動へ変える場合は、その明示的な状態選択と有効化をレビューに記録する。必要な変更能力がなければ準備できない。

プラグインの「Normal状態を保つ」は保存時の状態を復帰すること。保存時に無効なら無効のままで、有効化と表示しない。プラグインをNormal以上に有効化する操作はこの版に含めない。全体の無効化はSkillだけの手動化とは異なり、提供するMCP、hook、app等にも影響し得る。その構成と確認できない範囲をレビューに出す。外部サービス側の接続・認証の削除や権限変更は行わない。

## 共通で保持するもの

メモリ、標準の作業継続、権限、管理ポリシー、必須のプロジェクト要件、標準提供の条件を保持する。利用者が追加した任意の対象だけを明示登録する。user scope、ホーム配下、名前、ファイルの自己申告は任意性の証拠にならない。

正式に登録されたUnharnessの管理Skill・起動・状態確認・切替・復旧接続は共通保持する。管理機能を含むプラグイン全体も無効化対象にしない。この例外を任意の制作・相談Skillや同名の別プラグインへ広げない。未登録・未確認・必須・制御不能の残存要素は別表示し、AI全体が空になったとは説明しない。

## 合成規則

通常Skillは「無効 < 手動 < 自動」の順に扱う。零式は全登録任意Skillの無効・手動を明示し、限定解除はそこから上げる項目だけを記録する。限定解除に独立した全状態を入力させず、零式の手動を限定解除だけで無効にする要求は拒否する。零式の変更時には両モードの結果を同時にレビューする。

プラグインも零式の保持集合と限定解除だけの追加集合から結果を合成する。重複を数えず、継承項目を限定解除内で外す入力は受け付けない。零式から外した項目を限定解除だけに保つには新しいレビューで明示的に追加する。Normalと解除モードの間に包含関係や性能改善は約束しない。

GUI・CLI・MCPは同じ純粋な合成規則と保存サービスを使う。入力から設定先パス、プラグインの由来、変更能力を作らない。

## プラグインの確認と変更境界

Skill登録とプラグイン登録を分ける。プラグインの登録は、ホストが管理する導入済みIDと版、掲載元、ローカル構成の版、Normalの有効状態と対応するuser設定キー、影響する機能、任意性と保持理由を固定する。プラグイン内のSkillを通常Skillとして登録してキャッシュを書き換えない。

公式掲載はホスト提供者の公開ディレクトリと導入記録を結び付けて確認する。第三者製でも掲載対象になり得る。個人・組織マーケット、直接Git追加、同名のローカルコピー、AIや利用者の自己申告は掲載の証拠にならない。「公式由来を確認・公式対象外・未確認」と、導入状態・任意性・変更能力を別々に保持する。未確認を自動的に無効化しない。

保存済みの由来確認は、確認時の導入IDとローカル構成が一致する範囲で使用する。ローカルハッシュを公開配布物の真正性の証明と説明しない。更新・追加・欠落・入れ替えで確認を別内容へ流用せず、新しいレビューを要求する。通常の切替にオンライン照会を必須としない。

Mac Codexの最初の制御は、登録したプラグインIDのuser設定enabledのみに限定する。ホストの標準編集機能を新しい所有一時profile内で使って差分を作り、既存の計画・中断記録・独立編集検査を通して設定を準備する。無関係なプラグイン値、接続設定、コメント、管理レイヤーを保持する。Native APIが実験段階なら、確認した版と取得経路に限定し、未対応環境では明示的に利用不可にする。

## 保存・履歴・復旧

v3設定の採用は記録だけを変更し、現在の準備状態を変えない。通常Skillとプラグインの両モードの状態・確認済み版・差分を凍結する。実際の準備は別操作にする。

登録の追加は後継scopeとNormalを作り、元のNormalと全履歴を残す。プラグイン設定の追加管理境界を旧v1/v2保存版へ注入しない。以前のお気に入りを新しい登録範囲で復帰するとき、当時未登録のプラグインは登録時のNormal値を用い、その適応を表示する。旧比較は当時のscope・版のままにする。

新しいworkspace形式は旧writerを拒否する。登録追加・設定採用の中断は独立したNode-only復旧経路で取り消せる。Normal・お気に入り・中断復旧に、プラグインの公開照会・再インストール・Codex・YAML依存を必須にしない。復帰するのは保存済み設定であり、欠落したプラグインの配布物や外部認証を復元したとは表示しない。独立編集は勝手に上書きしない。

## CLI・AI接続の入力契約

既存の非対話JSON形式 `node bin/unharness.mjs sources <操作> --json '<object>'` を使う。
主用途はAI接続とスクリプトで、端末からも同じレビュー内容を確認できる。
設定先は登録workspaceのcontextだけから決め、環境変数・既定値で別profileへ切り替えない。

| CLI操作 / MCP名 | 必須入力（CLIのみworkspaceを追加） | 結果 |
| --- | --- | --- |
| `plugin-enrollment-inventory` / `plugin_enrollment_inventory` | なし | 導入済み候補、利用可否、discoveryId。任意性は未確認 |
| `review-plugin-enrollment` / `review_plugin_enrollment` | discoveryId、additions | 公式掲載・構成を確認し、固定した登録レビューを作る |
| `apply-plugin-enrollment` / `apply_plugin_enrollment` | reviewId | 登録だけを採用。新scopeIdとNormal版、設定保存・準備が必要な状態を返す |
| `setup` / `read_setup` | schemaVersionは任意で2または3 | 既定はworkspace形式以上のinventory。新規v3案では3を指定 |

additionsは1〜32件の `{pluginId, origin, reason, optional:true}`。
originはselfまたはexternal。任意性が未確認ならレビューへ進まない。
パス・本文・設定キー・掲載証拠・変更能力を入力で指定できない。
MCPで記録を作る操作は既存のconnectionId/requestIdを用い、同じ操作の再取得では同じIDを使う。

レビューは設定ファイルを書き換えない。採用後もモード準備は別操作で、Normalと古い保存版を残す。
確認済みの役割と範囲に対する実行依頼を採用の承認として扱い、追加の対話フラグは設けない。
成功はJSONをstdoutに出して終了0、実行時エラーは固定kindのJSONをstderrに出して終了1、
コマンド構文の不備は終了2。秘密情報やNativeの生エラーは出力しない。

例：`node bin/unharness.mjs sources plugin-enrollment-inventory --json '{"workspace":"/absolute/owned-workspace"}'`

## 検証と表示（受入れ）

準備済み、特定の新しいタスクで記録が一致、未確認を分ける。無効・手動・自動の件数は登録した通常Skillに限定し、プラグイン数と混ぜない。プラグインには保存Normal、要求した状態、確認した導入/設定状態、Skill・MCP等の確認結果を別々に示す。Skillのカタログ不在だけでプラグイン全機能の停止を断定しない。

受入れには、混在する通常Skillの3状態と継承、公式掲載の正負例、プラグイン全体OFF/Normal復帰、Normal無効の保持、必須対象の拒否、無関係な値とコメントの保持、古い保存版の復帰、更新・欠落・中断・独立編集、旧writer拒否を含む。さらに実際のMac CodexでGUIとAIの両入口、新しいタスクの読み込み、明示Skill利用、比較、独立復旧を確認する。合成データや設定ファイルの準備だけで実機対応を宣言しない。
