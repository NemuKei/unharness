# Local workbench as the operating surface

Accepted by the maintainer on 2026-09-14 after comparing local-only daily use with public-to-local pairing. The public site remains useful for introduction, synthetic demos, installation and updates. Daily mode selection, appearance, work records, comparison and recovery happen in the bundled local GUI opened through the management Skill.

## Everyday journey

Discover Unharness on the site → ask Codex to open/install it → the Skill verifies the registered context and opens the running local workbench → use that one screen. Users do not type a localhost URL or approve a public-site connection to do ordinary work. Opening preserves the current mode and records. Local MCP and GUI continue to use the same guarded services.

The public site offers a Codex draft and a clearly labelled copy fallback for opening the local workbench. Draft creation/copying is not a sent instruction, successful installation or verified launch. Website content cannot select a private path/profile or recapture Normal.

## Migration

- Remove new pairing from normal local navigation and the management Skill. The compatibility `request_public_connection` command returns a verified local workbench URL and `publicConnection: retired`; it issues no new ticket or permission.
- Normal public visitors see introduction, demos, installation and local launch guidance. Public operating tools are not registered for an ordinary unpaired visit.
- Previously issued, bounded links/operation receipts retain their legacy surface until their existing lifecycle ends. Do not extend grants, rewrite old receipts, relabel a missing result as not executed, or repeat an uncertain operation with a new ID. The legacy v2 transport remains for already installed clients during migration; it is not the default product journey.
- Keep `public_operation_status` and a folded local result lookup for earlier operation IDs, including after expiry or GUI shutdown. Settings, Normal versions, favorites, artwork and work records are not migrated, deleted or recaptured.
- Preserve loopback binding, Host/origin/token checks, exact paths, independent-edit checks and offline recovery. Local-first UI does not remove local access controls.

The earlier [domain-entry contract](spec-domain-entry.md) remains the protocol and release-history reference. This change does not by itself replace a published archive, update an installation, deploy the website or add Windows/Claude native qualification.

## Acceptance

An ordinary visitor cannot initiate a public operating session from the site's navigation. Opening the installed product lands in its local screen, with no pairing panel among mode or work-record controls. Existing public receipts remain readable locally. The same saved state is available after the new UI is installed, and offline recovery retains its independent path.
