# Unharness — Mac開発プレビュー

バージョン 0.0.1。Apple SiliconのMacとCodex Desktopを対象にした開発プレビューです。公開接続はv2です。対応状況と確認済みの範囲は配布ページに記載しています。

## Codexに導入を頼む

この展開済みフォルダをCodexに渡し、次の文章を依頼してください。利用者がGit・npm・導入コマンドを手入力する必要はありません。

> このフォルダのUnharnessを、このMacで使うCodex Desktopへ導入してください。下の導入手順と配布物の整合性を確認し、使っているCodexのプロファイルとプロジェクトを確かめて進めてください。保存済みのNormal、メモリや権限などの共通設定を保持してください。導入後はUnharnessのローカル画面を開き、対象の確認と初回のNormal保存まで案内してください。解除対象は私が確認して選びます。

## 導入を担当するAI向け

1. [この版の配布ページ](https://github.com/NemuKei/unharness/releases/tag/v0.0.1)に示されたZIPのSHA-256と入手ファイルを照合します。別の公開URLや最新版を推測して取得しないでください。
2. インストール済みCodexの実行ファイルと、このタスクで使用する実際のCodexホーム・プロジェクトを確認します。プラグインの作業場所や環境変数だけでは利用者の選択を確定しません。不明な選択は利用者に確認してください。
3. 同梱Nodeは `plugins/unharness/runtime/bin/node` です。`plugins/unharness/distribution.json` と同梱の検証処理で配布内容を照合します。同梱Nodeを使い、利用者にNodeやnpmの追加導入を要求しません。
4. このフォルダの `.agents/plugins/marketplace.json` を、選択したCodexホームのローカルマーケットプレイスとして追加し、`unharness@deltahelmlab-unharness` を導入します。既存の同名登録が別の場所を指す場合は置き換えず、差異を確認してください。コマンドを実行する前に、選択したCodexホームを `CODEX_HOME` として指定した子プロセスを用意します。コマンド例のパスは確認した実際の値へ置き換え、引数として安全に渡します。

```text
<確認したCodex実行ファイル> plugin marketplace add <この展開済みフォルダ> --json
<確認したCodex実行ファイル> plugin add unharness@deltahelmlab-unharness --json
```

5. 導入前後の共通設定を照合し、Unharnessの登録以外の変更があれば止めて確認します。グローバルな環境変数・実行権限・既存の別マーケットプレイスは保持します。
6. Codex側でUnharnessのMCPと管理Skillを読み直し、`status` と `installation_status` で導入先を確認します。現在のタスクにまだ出ていない場合は、新しいタスクで「アンハーネスを開いて」と依頼する手順を案内します。
7. 未設定なら、導入済みの管理Skillに従ってローカル接続を設定し、独立した復旧コピーを確認します。続いて `status` → `open_workbench` でローカル画面を開きます。初回の対象登録とNormal保存は画面で利用者が確認します。

フォルダは導入元として記録されます。更新・移動・削除の前に、その導入元と保存済みの復旧経路を確認してください。プラグインのキャッシュや配布フォルダを、Normal・作品・比較の保存先として扱わないでください。

詳細は `plugins/unharness/docs/plugin-connection.md` と `plugins/unharness/docs/plugin-recovery.md` にあります。公開サイトへの接続許可、モードの準備、実行中のタスクへの読み込みは別々に確認します。
