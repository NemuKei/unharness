# Unharness

ハーネスを、気軽に試着する。

**外して、比べて、気に入ったら残す。**

Skillや追加指示の組み合わせを、自分の仕事で試す。今のモデルと環境に合う構成を見つけたら、お気に入りに保存してまた使える。

[English](README.md)

> **公開時の体験を描くREADME草案です。** 実現性の検証に使う、一覧診断、一時ファイルを使うソース制御、デスクトップのローカル記録を読む診断CLIを用意しました。以下は目指す製品の体験であり、個人設定への切替・比較実行・本番用の復帰はまだ実装・検証されていません。macOS・Windowsを最初から対象とし、Codexデスクトップ、続いてClaude Codeデスクトップへ対応する方針です。

**無料で使え、有料APIや運用サーバーを必要としない設計です。** Unharnessの継続的な運用サービス費はゼロを前提とし、ユーザーが使うAIの契約・使用量は別に扱います。オリジナルの3案制作を含む外観とカード出力は、モデルを呼ばずローカルでも行える方針です。[実現性と制約](docs/feasibility.md)を参照してください。

## 開発用の診断CLI

Node.js 24以上とネイティブのCodex実行ファイルが使える環境で、このrepoから実行します。追加パッケージは不要です。

```text
node --test
node bin/unharness.mjs inspect --cwd . --output local-evidence/codex-probe.json
node bin/unharness.mjs probe-controls --output local-evidence/source-controls.json
```

`inspect` は別プロセスのCodexから、設定本文などを含まない一覧の要約を取得します。設定変更やデスクトップのモード切替は行いません。[使い方とWindows側への引き継ぎ](docs/codex-probe.md)を参照してください。

`probe-controls` は自分で作った一時的なAGENTS・Skillを6条件で切り替え、Codexが組み立てる入力を確認して後片付けします。個人設定は編集せず、モデルの実行も始めません。確認対象は検証用ソースの挙動であり、デスクトップのモード適用ではありません。[Windowsネイティブでの基準結果](docs/evidence/2026-09-07-windows-baseline.md)には、完了した一覧・専用ソースの確認を記録していますが、デスクトップのモード確認ではありません。[ソース制御の診断](docs/source-controls.md)に詳細があります。

`inspect-desktop --current` は選択中のタスクのローカル記録から、追加ソースや使用量の項目が記録されているかを調べます。本文やトークン合計は出力しません。`desktop-fixture create` は手動で新規タスクを始める検証用フォルダを用意し、専用データだけを復帰できます。WindowsネイティブではGUI経由で条件を満たす新規タスクを観測しましたが、baseline の記録は `not-matched-record` でした。更新通知後の新規タスクで再確認待ちです。モード適用やデスクトップ対応を確認したものではありません。[デスクトップ観測と復帰の手順](docs/desktop-observation.md)と[Windowsの新規タスク証跡](docs/evidence/2026-09-07-windows-fresh-task.md)を参照してください。 Macの専用データでは反映・復帰を観測しましたが、Skill一覧が古い状態を保つ場合がありました。`desktop-fixture refresh` は検証専用ファイルの更新通知を行い、その後のタスクで反映を確かめるためのコマンドです。

`loadouts` で、専用データの登録、版付きのお気に入り保存、変更直前の復旧点、競合を避ける復帰、保存した版とタスク記録の関連付けを扱えます。ローカルGUIも同じ処理を使います。個人設定への対応とMCPの接続は今後の対象です。[登録・保存・復帰の使い方](docs/loadouts.md)を参照してください。 [Macの実機確認](docs/evidence/2026-09-07-saved-loadout-desktop-macos.md)では、保存した専用データの版と新規タスクの記録を結び付け、通常版への復帰まで確認しました。Windowsの最初の新規タスクは条件を満たしましたが baseline と一致せず、保存版との関連付け成功にはなっていません。

## ローカルGUIで試す

Node.js 24以上で、開発用の画面をビルドして起動します。

```text
npm ci --ignore-scripts
npm run check
npm run build
npm run gui
```

表示されたローカルURLを開きます。保存版の選択・差分確認・適用、現在の設定の保存、新規タスク記録の確認、復旧点への復帰を操作できます。デモを起動するたびに `.unharness/` 内へ新しい専用環境を作り、表示された保存先・scope・再開用の引数で同じ環境を開き直せます。画面には検証専用であることを明示しており、個人のCodex設定は変更しません。完全なモード対応を示すものではありません。[MacでのGUI確認](docs/evidence/2026-09-07-local-gui-macos.md)と、限定的な[Windowsネイティブの確認](docs/evidence/2026-09-07-windows-baseline.md)があります。Windowsの初回GUI確認は以前の演出を対象としており、ブラウザー再起動、演出オフ、狭い表示幅、今回のアニメーションは未確認です。[GUIの使い方と復帰](docs/gui.md)を参照してください。

## 「これを外したらどうなる？」を、気軽に試す

AIに仕事をしてもらうために、Skillや指示、作業手順を追加してきた。今度は、そのどれが今のモデルと目の前の仕事に合っているかを確かめたい。

今の構成を保存し、モードを1つ選んで自分の仕事に使う。結果を振り返り、役立つものを戻し、しっくりくる組み合わせをお気に入りに残す。詳しく比べたくなったら、同じ開始条件から別のモードで依頼を再実行できます。比較して今の構成がよいと分かったら、そのまま使い続けられます。

モデルの更新、新しいSkillの追加、プロジェクトの変化、AIの進め方への小さな違和感。どれも、別の構成を試すきっかけになります。

ここでいう**ハーネス**は、Skill、常設の指示、自動処理など、AIの仕事の仕方を形作る周辺の仕組みです。**装備セット**は、それらの組み合わせと、有効・手動のみ・停止の状態を保存したものです。

## 最初の小さなお試し

1. **今の構成を残す。** 「今の設定をお気に入りに登録して」と頼むか、星のボタンで保存します。
2. **別のモードを選ぶ。** 通常装備、対象Skillを手動のみで使う限定解除、管理対象の追加要素を外す零式から選びます。
3. **新しく試す。** 選んだモードで新しいタスクを始め、依頼と開始条件を記録します。
4. **自分の仕事を振り返る。** 成果物、変更内容、時間、取得できる使用量、自分の評価メモを、保存した結果と一緒に見ます。
5. **合う組み合わせを残す。** 調整した構成をお気に入りに登録して、また使います。以前の装備も呼び戻せます。

得たいのは、自分の仕事に対して理由を持って選べること。指示を減らした結果は、改善、変化なし、大事なものが抜けた、のどれにもなり得ます。

初期の体験は、モードを1つ選んで使う形です。同じ指示を3モードへ自動投入することはなく、条件を揃えた再実行は必要に応じて後から行います。異なる日常業務の記録だけで、モードによる性能改善・悪化を断定しません。

数値比較では、必要な品質へ到達するまでのトークンと試行回数を、本人の好みと併記する方針です。動作確認と、評価項目を決めた採点は分けて扱います。[測定の仕様](docs/comparison-metrics.md)を整理しており、実行時の使用量取得と採点は今後の実装対象です。

## 比較を始める3モード

| モード | 目指す動作 |
| --- | --- |
| 通常装備 | 保存した構成を使います。 |
| 限定解除 — UNSEAL | 対象のSkillを手動呼び出しのみにし、他の追加指示を維持します。 |
| 零式 — TRUEFORM | 対応する管理範囲内で、対象Skill・追加手順・作業を誘導するhook・メモリの自動読み込みを止めます。 |

仕事の条件と実行権限は揃えて保ちます。復帰に必要な最小限の操作用接続口など、残る要素も表示します。何が可能で、どう反映されるかは、対応するツールのバージョンごとに確かめます。

3モードを出発点に、自分で調整した組み合わせもお気に入りとして保存できます。

## 画面でも、AIへの依頼でも

Web画面と自然言語の依頼から、同じローカル処理を呼ぶ体験を目指します。

- 「限定解除に切り替えて」
- 「この依頼を零式でも試して」
- 「今の設定をお気に入りに登録して」
- 「この組み合わせをレビュー用として保存して」
- 「お気に入りのレビュー用に戻して」
- 「今、何が有効？」

お気に入りには、登録した時点の構成を残します。その後に設定を変えても、お気に入りの中身を勝手に変更しません。登録時の名前は省略でき、後から変更できます。

## 装備の変化が見える

ビジュアルは、ドット絵の機械格納庫。外装が開き、内側のAIが見え、零式では本体が姿を現す方向です。AIへの依頼による切替も、Web画面からの操作と同じ状態表示・演出へつながります。

![通常装備、限定解除、零式でAI本体が現れる静止画の構想](docs/assets/04-mecha-release-stages.png)

*当初の静止画によるデザイン案です。現在のGUIは、検証対象を明示した小さな操作フローを実装しています。*

GUIは装備のシーン・演出にPixiJS、操作ボタン・読みやすい状態表示にReactとHTML/CSSを使います。選んだ元絵の装甲・ケーブル・枝状のコアを保ち、待機中は浮遊や光が動き、切替時は3つの元絵を表示中の状態から滑らかにつなぎます。戻す方向も同じ経路をたどり、再生時の画像生成は不要です。タスク記録やIDなどの技術項目は、折りたたんだ開発用の詳細にまとめています。[描画方針](docs/design.md#selected-rendering-stack)と[同梱素材](docs/gui-artwork.md)を参照してください。外観のランダムな組み立てやオリジナル形態の制作は、今後の実装対象です。

比較で役立つと分かったハーネスは、本体を支える装甲や共鳴する装備としても表現する方針です。未測定時は中立に描き、見た目と測定結果を分けて扱います。

3案から選んだオリジナルの姿は、再利用できる外観コレクションに残します。現在の条件で悪化が確認された場合はBAD版だけを使い、未判定なら中立の姿を使う設計です。獲得した装備は失われず、外観を選ぶ操作で実際のハーネス構成は変わりません。コレクションと評価に応じた表示は、今後の実装対象です。

演出はオフにできます。装備の構成は変わらず、状態も文字で確認できます。演出の設定は、お気に入りのハーネス構成とは別に保存します。

## 何を変えたかが分かる

選んだモード、次のタスク向けに用意した設定、実際に確認できた状態を区別して表示します。会話へ読み込み済みの指示は文脈に残るため、比較は新しいタスクから始めます。

比較記録には、装備の版、モデルと推論設定、依頼、開始ファイル、道具、権限、関係するメモリ条件を残す設計です。分離できない条件や取得できない指標は、そのまま明記します。一度の実行は一つの観測として扱います。

復帰では、管理対象の設定を戻し、別途行われた編集を黙って上書きしない設計にします。AIとの接続が失われても、外部の復帰手段を残します。対応する復帰範囲は、検証した手順とともに文書化します。

## 公開状況と参加

UnharnessはOSS公開に向けて準備中です。インストール手順と検証済みの対応表はまだありません。両OSを最初から対象にし、次の順番で実装します。

| アプリ | macOS | Windows |
| --- | --- | --- |
| Codexデスクトップ | 第1段階の対象 | 第1段階の対象 |
| Claude Codeデスクトップ | 第2段階の対象 | 第2段階の対象 |

これは実装対象の表であり、動作確認済みという意味ではありません。[互換性と検証記録](docs/compatibility.md)へ、確認した結果を残していきます。

初期には、互換性を確かめられる再現情報、小さな比較例、保存・お試し・比較・復帰の流れへのフィードバック、Docsの改善が役立ちます。開発参加の手順、ライセンス、報告窓口は、専用repoで公開までに整えます。
